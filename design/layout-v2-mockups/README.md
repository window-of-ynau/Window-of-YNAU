## 三张宽屏证明了什么

1. **分界在三套底色下都成立**：A 靠 `#F7F7F7` 底色差 + `#E8E8E8` 线；B 靠 5% 白的玻璃面 + 10% 白线；C 靠 `#FAF9F5` 纸面 + `#E6DFD8` 线。
2. **标题**：`云农之窗` 为主标题（C 主题用衬线 500），`对话` 为副标题；窗口标题不再只有名字。
3. **对齐**：左侧蓝色刻度标出汉堡与底部设置落在同一条 `x=32` 竖线上（展开/折叠都一样，因为都走 64dp 图标列）。

## 窄屏两变体的取舍（一句话）

- **变体 A（左 rail 64）**：保持"左导航"的心智模型、切页不遮挡内容；代价是 480 宽被吃掉 13%，且**必须让内容左让 64**——我第一版没让，rail 直接盖住了问候语和输入框（截图里能看出来），这条要写进实现。
- **变体 B（底部导航）**：内容拿到全宽、拇指可达，是移动端惯例；代价是在 Windows 桌面上显得不像桌面应用，且 4 个标签的文字要压到 10.5px。

**建议**：`平台 == Android && 宽度 < 600` 用 **B**；Windows 窄窗用 **A**（桌面窗口极少 <600，真要那么窄也是临时拖拽）。两者可共存，用一个 `Platform.isAndroid` 分支即可。

## 渲染过程中发现、建议实现时注意的地方

1. **rail 浮层必须让位**：`rail` 覆盖内容会盖住问候语与输入框左侧（第一版实拍），实现时内容 `padding-left: 64`，或改成"默认隐藏、点汉堡后覆盖"。
2. **窄屏 4 个 chip 会折成两行**（480 宽下），视觉上略挤；建议 <600 时只保留 **3 个** chip，或把 chip 字号降到 12。
3. **C 主题的分界最弱**：`#FAF9F5` 与 `#F5F4ED` 的明度差很小（约 2%），几乎全靠那条 1px 线。若真机上觉得"没分界"，把线降到 `#DED6C8` 或给侧栏加 2% 的暖灰底。
4. **B 主题的玻璃侧栏**在渐变上会"上浅下深"（渐变本身有方向），若显脏可改成纯 `rgba(255,255,255,.04)` 平铺再加线。
5. **两行标题**让 AppBar 从 56 → 60，宽屏 800 高下无感；但 480×800 的窄屏我按规格只留主标题（52），否则两行会把内容区再压 8dp。
6. **聊天列宽**：宽 768 / 中 720 是我按"中文 35–45 字"反推的，若 owner 觉得空态居中后两侧太空，可以收到 640–680（这也是 C 主题圆桌稿里的 640）。
