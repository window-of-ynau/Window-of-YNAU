## 1. 栅格与断点

| 档 | 窗口宽度 | 左栏宽度 | 内容区左右内边距 | 聊天列最大宽度 | AppBar 高 |
|---|---|---|---|---|---|
| **窄** | `< 600` | rail **64**（浮层覆盖内容，带阴影；或完全隐藏） | **16** | 满宽（不设上限） | **52** |
| **中** | `600 – 839` | **200**（默认展开，可折叠到 64） | **20** | **720** | **56** |
| **宽** | `≥ 840` | **224**（默认展开，可折叠到 64） | **24** | **768** | **60** |

折叠（rail）不改变断点判定，只改变左栏宽度：`expanded → 224/200`，`collapsed → 64`。

**Flutter 常量（替换 `_HomeShellState` 现有三个常量）**

```dart
// 现状：kSidebarWidth = 256; kRailWidth = 64; kNarrowBreakpoint = 600;
static const double kRailWidth = 64;      // 不变：图标列宽 = rail 宽
static const double kSidebarMedium = 200; // 中屏展开宽
static const double kSidebarWide = 224;   // 宽屏展开宽（比现状 256 窄 32）
static const double kBpMedium = 600;      // 窄 → 中
static const double kBpWide = 840;        // 中 → 宽
static const double kIconColumn = 64;     // 图标列：所有图标的中心线都在 x = 32

double sidebarWidth(double windowWidth, bool collapsed) {
  if (collapsed) return kRailWidth;
  return windowWidth >= kBpWide ? kSidebarWide : kSidebarMedium;
}
double contentPadding(double windowWidth) =>
    windowWidth >= kBpWide ? 24 : (windowWidth >= kBpMedium ? 20 : 16);
double appBarHeight(double windowWidth) =>
    windowWidth >= kBpWide ? 60 : (windowWidth >= kBpMedium ? 56 : 52);
```

## 2. 左栏内部对齐（owner 的第三条）

**核心规则：所有图标都在同一条 64dp 宽的「图标列」里居中，中心线 x = 32。**

```
x=0                    64                       224
│←── 图标列 64 ──────→│←── 文字区 160 ────────→│
│        ╔══╗          │                        │
│        ║☰ ║ ← 汉堡   │  云农之窗              │  ← AppBar 行高 60
│        ╚══╝          │                        │
│                      │                        │
│        ┌──┐          │  对话                  │  ← 行高 36
│        │💬│          │                        │
│        └──┘          │                        │
│        ┌──┐          │  校园 · 3              │  ← 分组标签（仅展开态）
│        │🎓│          │                        │
│        └──┘          │                        │
│         ⋮            │         ⋮              │
│        ┌──┐          │                        │
│        │⚙ │ ← 设置   │  设置                  │  ← 与汉堡同一竖线
│        └──┘          │                        │
└──────────────────────┴────────────────────────┘
   图标中心 x=32            文字起点 x=72
```

| 项 | 数值 |
|---|---|
| 图标列宽 | **64**（= rail 宽，所以 rail 态整列就是侧栏） |
| 图标尺寸 | **20 × 20**（Material icon size 20） |
| 图标按钮 | **40 × 40**（点击区），在 64 列内居中 → 左内边距 **12**，中心 **x = 32** |
| 汉堡按钮 | 同上 40×40，**放在 AppBar leading，但外层套 `SizedBox(width: 64)` 居中**（现在 leading 是 48 槽、贴左 4，中心 28 → 与底部差 4） |
| 导航项行高 | **36**（展开态）；rail 态 = 40×40 按钮 |
| 导航项左内边距 | 0（图标列自带 64 宽），文字区左内边距 **8** → 文字起点 x = **72** |
| 分组标签 | 同列：左内边距 **72**，上 **12**、下 **4**；字号 **10 / w600 / 字距 0.12em / 颜色 `inkSoft`** |
| 顶部留白 | AppBar 下方到第一个分组标签 **8** |
| 底部留白 | 设置按钮下沿到侧栏底 **12** |
| 侧栏底部（设置） | 与汉堡同列：`SizedBox(width: 64)` + 居中 40×40 按钮；展开态右侧仍显示「设置」文字（文字起点同样 x=72） |

> 这样无论展开还是折叠，汉堡与底部设置的**中心线永远是同一条 x = 32**；折叠后 64 宽侧栏里两者自然上下对齐。

## 3. 分界方式：底色差 + 1px 主题细线（双保险）

**为什么两者都要**：只靠线，浅色主题 + 高分屏缩放时线会「消失」；只靠底色差，在深色玻璃主题（B）上对比不足。两者叠加后三套主题都稳定。

| 主题 | 侧栏底色 | 内容区底色 | 分界线颜色 | 视觉结果 |
|---|---|---|---|---|
| A 极简黑白 | `surface` `#F7F7F7` | `canvas` `#FFFFFF` | `hairline` `#E8E8E8` | 浅灰条 + 发丝线 |
| B 深蓝玻璃 | `rgba(255,255,255,0.05)` 叠在渐变上 | 画布渐变（透明 Scaffold） | `rgba(255,255,255,0.10)` | 暗色玻璃条 + 亮线 |
| C 书本质感 | `surface` `#FAF9F5`（比画布亮） | `canvas` `#F5F4ED`（羊皮纸） | `hairline` `#E6DFD8` | 纸页白边 + 细线 |

**实现**：把 `Row(children: [sidebar, VerticalDivider(width: 1), Expanded(panes)])`（`main.dart:306`）改成

```dart
children: <Widget>[
  sidebar,                                   // 自带底色 surface
  Container(width: 1, color: tokens.hairline), // 主题细线，不要 VerticalDivider 的默认色
  Expanded(child: panes),
],
```

- 侧栏容器：`color: tokens.surface`（B 主题下用 `GlassPanel(role: GlassRole.flat)` 的等效半透明色即可，不额外加模糊）；
- **窄屏 + 折叠**时侧栏是浮层：此时**不画那条线**，改用 `Material(elevation: 8)` 的投影 + 12 圆角右侧（现状是 elevation 2，偏弱）。

## 4. 标题区处理（删掉那条横杠）

### 4.1 删掉的东西
- `main.dart:513` 的 `const Divider(height: 1)` —— 它夹在导航列表与底部设置之间，**没有任何信息量**，owner 说的"只有一条横杠"就是它。
- AppBar 现在只有页面名（`title: Text(destination?.label ?? '云农之窗')`），没有产品名。

### 4.2 新的标题排法（推荐：主 + 副两行）

```
┌──────────────────────────────────────────────┐
│ ☰   云农之窗                       ⚙         │  ← AppBar 60
│     对话                                       │
└──────────────────────────────────────────────┘
      ↑ 主标题 17/600（C 主题：衬线 17/500）  ↑ 副标题 12/400 inkSoft
```

| 位置 | 字号 / 字重 | 颜色 | 行高 | 说明 |
|---|---|---|---|---|
| 主标题「云农之窗」 | **17 / 600**（C：**17 / 500 衬线**） | `ink` | 1.25 | 与窗口标题一致 |
| 副标题（当前页名） | **12 / 400** | `inkSoft` | 1.3 | 页名变化时只换这一行 |
| 两行间距 | **1** | — | — | 整块 `Column(mainAxisSize: min, crossAxisAlignment: start)` 垂直居中 |
| 左对齐起点 | x = **72**（与侧栏文字同一列，视觉上形成一条竖线） | — | — | — |

**窄屏（< 600）降级**：AppBar 52，只显示主标题 17/600，副标题隐藏；页面名由左侧 rail 的选中图标承担。

**备选方案（一行式）**：`云农之窗 · 对话`，主标题 17/600 + 分隔符 12 `inkSoft` + 页名 12 `inkSoft`。**不推荐**——两行能同时容纳产品名与页名，且窄屏降级更自然。

### 4.3 窗口标题（OS 层）
`windows/runner/main.cpp:30` → `window.Create(L"云农之窗", origin, size)`；
`windows/runner/Runner.rc` 的 `FileDescription` / `ProductName` 同步为「云农之窗」（任务栏与安装向导显示的就是这个）。

## 7. 验收清单（lead-client 落地后可直接照这几条测）

1. **窗口标题**：Windows 任务栏 hover / 属性页显示「云农之窗」，不再是 `yunong`；
2. **无横杠**：侧栏导航与底部设置之间没有 `Divider`（可用 `find.byType(Divider)` 断言 0 个）；
3. **两栏分界**：分界线颜色 == `tokens.hairline`（三主题各取一次），侧栏底色 == `tokens.surface`；
4. **对齐**：设置按钮中心 x 与汉堡中心 x 偏差 **< 1dp**（`tester.getCenter(...)` 断言）；折叠/展开两态都要测；
5. **宽度**：1280 宽窗口下侧栏 == **224**；760 下 == **200**；480 折叠 == **64**；
6. **标题**：宽/中屏 AppBar 里有「云农之窗」与当前页名两段文字；窄屏只有「云农之窗」。

## 8. 已知取舍

- **224 vs 200**：宽屏 224 能放下「马克思主义基本原理」这类长课名（约 14 字 @13px ≈ 182 + 图标列 64 = 246 会折行，所以长名仍会省略号，但比现状 256 少浪费 32dp）；若实测截断过多，把宽屏侧栏回调到 **240**，其余不变。
- **两行标题**会让 AppBar 从 56 涨到 60（宽屏），内容区可用高度少 4dp——可接受，换来产品名常驻。
- **窄屏浮层 elevation 8** 是经验值，若 B 主题（玻璃）上显脏，可降到 4 并改用 1px 右侧细线。
