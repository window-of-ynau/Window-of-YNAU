# 用真实账号怎么验（门户接口取课表，3 步）

> 前置：Windows，开发者模式已开，`nuget.exe` 在 `PATH`，能访问 `ssoo.ynau.edu.cn` / `one.ynau.edu.cn`。
> 构建：`scripts/build-windows.ps1`（或 `flutter --no-version-check build windows --debug`，再把 `yunong_core.dll` 放到 exe 旁）。

## 第 1 步：登录（会复用会话）

1. 启动 `yunong.exe` → 左侧「我的课表」→ 点「登录并抓取课表」；
2. WebView 打开**统一身份认证** `ssoo.ynau.edu.cn/lyuapServer/login`，用真实学号密码登录；
3. 登录成功后自动到门户 `one.ynau.edu.cn/#/index5`，顶部提示变成
   「请先登录；登录后打开一次门户里的课表卡片，会自动抓取」→「已登录…」。

**看什么**：登录页能正常显示、能输入、能提交（如果登录页白屏，先查校园网/VPN）。

## 第 2 步：打开一次课表卡片（触发接口捕获）

1. 在门户里切到课表卡片/课表页（就是平时看课表那个入口），**把周选择器随便停在一周**；
2. App 的注入脚本会 hook 到这次 `queryAWeekSchedule` 请求，拿到 `cardId` 与 `years`，
   然后自动并发拉 1..weekcount 周；
3. 页面自动关闭，课表列表出现课程，提示形如
   「已从门户接口抓取 20 周，本学期 N 门课」（有缺周时会写「缺 X 周（已入库其余周）」）。

**看什么**：
- 周选择器停在哪一周都行（脚本不依赖具体周号）；
- 如果提示「没抓到课表接口：请先在门户里打开一次课表卡片」→ 说明卡片没被点开，重来第 2 步；
- 如果提示「登录态已失效，请重新登录」→ 会话过期，回第 1 步。

## 第 3 步：核对学期开始日与课程

1. 课表页顶部会出现「学期开始日（第 1 周周一）：2026-09-07 · 第 1 周：09-07 ~ 09-13 · 今天按此算第 N 周」；
   - 如果和你认知的一致 → 点「确认」（会持久化，下次直接用）；
   - 不一致 → 点「修改」选正确日期再确认（**这一步必须由人确认，程序不猜**）；
2. 核对课程：把几门课和你门户里的课表对一下——重点看
   - 连续节次是否合并成区间（例如周一 1-2 节而不是两条记录）；
   - 周次是否压缩成 `1-16` / `1-8,10-16` 这种；
   - 教室、教师是否为空/错位（如果错位，把接口返回的一格原文（去掉姓名学号）贴到工单里）。
3. 退出 App 再打开，重复第 1 步应**不需要重新登录**（会话复用），且课表仍在。

## 判定

| 结果 | 结论 |
|---|---|
| 三步都过，课程与门户一致 | PASS |
| 能登录、能抓到周数据，但课程合并/周次不对 | 半通过：贴出接口样本（脱敏）开 issue |
| 第 1 步就白屏/登录不了 | 环境问题（校园网/VPN/证书），先排除网络 |
| 第 2 步抓不到模板 | 门户页面结构变了：贴一条 he 截图，我们改 hook |

> 隐私：任何反馈里**不要**贴学号、姓名、Cookie、完整 URL 的 query（`ticket`/`cardId` 都算凭据）。
