# ADR 模板

> 复制本文件到 `docs/adr/NNNN-简短标题.md`（编号连续，四位）。
> 判断"这算不算 ADR"：**如果它不能被一句话说成"我们划了一条边界"**，那它就不是架构决策，写进设计文档即可。

---

## ADR-NNNN 标题

**状态**：提议 / 已定 / 已废弃（被 ADR-XXXX 取代）
**日期**：YYYY-MM-DD
**决策者**：谁拍的板

### 背景

现在是什么状况？为什么必须做选择？（三句话内说清）

### 决策

我们选择 ______。
用一句话写死；不要写"我们倾向于"。

### 边界

- 这条决策**划定**了什么：______
- 什么东西**绝不能**越过这条线：______
- 数据/请求从哪一侧发起、哪一侧见证：______

### 越界防范

（怎么保证别人（包括三个月后的自己）不会无意中越界：代码隔离、CI 检查、日志脱敏、迁移脚本里干脆不建表……）

### 失败模式

| 这一侧塌了 | 系统会怎样 | 用户看到什么 |
|---|---|---|
| | | |

### 否决的备选

| 备选 | 否决理由（要有数据或事实，不要只说"更复杂"） |
|---|---|
| | |

### 代价（必须诚实地写出来）

（这条决策牺牲了什么：体验、工期、成本、可扩展性……）

### 复审条件

什么情况下应该回来重新讨论这条决策？（例如：日活超过 1 万、校方开放 OAuth、上游改价）
