## 1. 设计原则（架构的裁判）

| # | 原则 | 落到结构上 |
|---|---|---|
| A1 | **凭据不出端** | 学校 Cookie、用户 Key 只在端侧安全存储；服务端无凭据存储 |
| A2 | **端做重活，云做轻活** | 解析、压缩、记忆、日历生成都在端侧 Rust；云端只做鉴权/计费/审核/知识检索/模型代理 |
| A3 | **服务端无状态（对内容）** | 云端不存会话正文，只存用量与审计；重启不丢用户数据（数据在端上） |
| A4 | **能力而非命令** | 只有白名单能力，无 shell、无任意命令执行 |
| A5 | **双通道同构** | BYOK 直连与套餐代理共用一套 `ModelGateway` 与上下文装配逻辑 |
| A6 | **可测即可信** | 每个关键路径有 Benchmark 与契约测试，重构效果用数字说话 |

## 2. 总体架构

```
┌──────────────────────────── 客户端（Android / Windows / Web）───────────────────────────┐
│                                                                                        │
│  Flutter UI（一套代码）                                                                 │
│   ├─ 左导航：校务入口                                                                    │
│   ├─ 主区：对话 / 课表 / 日程 / 设置                                                     │
│   └─ 内置 WebView（flutter_inappwebview）                                                │
│        └─ 校务系统登录与取数：**所有对学校的请求在这里发生**                                │
│                                                                                        │
│  Rust Core（flutter_rust_bridge / FFI）                                                 │
│   ├─ keystore：Cookie 与 API Key 加密（Android Keystore / Windows DPAPI）                │
│   ├─ memory：本地 SQLite（会话、记忆、剪枝原文、图片、课表、日程）                          │
│   ├─ parser：PDF/PPT→图，Word/Excel/MD/TXT→文本                                          │
│   ├─ context：装配 + 55% 压缩 + 头尾剪枝 + memory:// 恢复                                 │
│   ├─ calendar：周次展开 + 冲突检测 + ICS 生成                                             │
│   └─ ModelGateway ──┬─ DirectProvider  ──▶ 模型厂商（BYOK，Key 不上云）                   │
│                     └─ CloudProxy ─────▶ 我们的服务端（套餐）                             │
└───────────────────────────────────┬────────────────────────────────────────────────────┘
                                    │ HTTPS + SSE（仅套餐通道与知识检索）
┌───────────────────────────────────▼────────────────────────────────────────────────────┐
│ 服务端（Rust / axum，单二进制）                                                          │
│  ├─ auth：注册/登录/Token/设备绑定                                                       │
│  ├─ model-proxy：转发 + 流式回传 + 中断传播（**Auto Review 未实现**）                     │
│  ├─ quota：并发闸门(50) + 单轮上限 + 429/Retry-After（用户配额/余额属 1.1）                │
│  ├─ knowledge：文档入库、分块、embedding、混合检索、rerank                                 │
│  ├─ usage：记账（user/tokens/cost/req_id）、套餐与激活码                                    │
│  ├─ metrics/logs：Prometheus 指标 + 结构化日志（脱敏）                                     │
│  └─ admin：发码/配额/知识审核                                                             │
└───────────────────────────────────┬────────────────────────────────────────────────────┘
                                    │
                     PostgreSQL（+ pgvector）  对象存储（原文/图片，可选）
```

**三条边界，记住就不会写错**：

1. **学校请求只在 WebView 里**（含内网资源）——服务端永远拿不到学校 Cookie；
2. **用户 Key 只在端上直连**——服务端看不到 BYOK 的 Key 与流量；
3. **会话正文默认不上云**——云端只有鉴权、配额、审核记录、知识库。

## 4. 架构决策记录（ADR）

**同级文档：[04-ADR.md](04-ADR.md) —— 那里是唯一事实来源。**

本项目共 17 条架构决策，每条都写清了「划定的边界 / 越界防范 / 失败模式 / 否决的备选」：

| ADR | 主题 | 一句话结论 |
|---|---|---|
| 01 | 三域划分 | 端 / 云 / 知识，一块数据只能有一个家 |
| 02 | 云端定位 | 控制面 + 过路面，默认不落正文 |
| 03 | 套餐通道 | 服务端代理 + 时效授权，**不发上游 Key** |
| 04 | BYOK | 端侧直连，Key 不出端 |
| 05 | 工具循环 | 无状态多轮请求（`turn_id` / ≤4 轮 / append-only / 按轮幂等） |
| 06 | Auto Review | 仅套餐通道；规则同步 + 模型异步（W2b 未实现） |
| 07 | 端侧核心 | Rust 胖核心 / Flutter 瘦 UI |
| 08 | 存储 | 端 SQLite / 云 PG，**云端没有 messages 表** |
| 09 | 检索分层 | 私有 BM25（可插拔）/ 公共向量 |
| 10 | 跨端 | 1.0 加密备份文件 / 1.1 E2EE，不做明文同步 |
| 11 | 身份 | 自注册为主；**只存 Argon2id 哈希、不转授会话** |
| 12 | 服务端形态 | 模块化单体 + PG 队列，1.0 单实例 |
| 13 | 协议适配 | 手写薄适配 + `shared` 单一契约 |
| 14 | 许可 | AGPL-3.0 + 商业双许可 + 数据权利 |
| 15 | 令牌形态 | 不透明串 + 只存 SHA-256 摘要，登出即刻失效（不用 JWT） |
| 16 | 契约可表达性 | C1 `tool_calls`（边说边调工具）+ C6 一事件多 `Chunk` |
| 17 | 并行调用归位 | C9 `Chunk::ToolCall.index`：分片参数按序号归位，wire 兼容 |

## 5. 数据架构

### 5.1 分层

```
端侧（隐私层，永不上云）                      云端（服务层）
├ sessions / messages（会话正文）             ├ users / devices / tokens
├ memory_items（记忆条目）                     ├ plans / quota / usage_samples
├ memory_blobs（**剪枝/压缩原文**，可恢复）     ├ knowledge_docs / chunks / embeddings
├ files_cache（用户文件解析结果）               ├ audit_logs（动作 + hash，不含正文）
├ calendar_events（日程）                       └ redeem_codes / model_configs
├ courses / terms（课表）
└ settings（加密的 Key/Cookie 引用）
```

### 5.2 端侧 SQLite（schema 草案）

```sql
CREATE TABLE sessions (
  id TEXT PRIMARY KEY, title TEXT, created_at INTEGER, updated_at INTEGER,
  summary TEXT                        -- 压缩后的会话摘要（进上下文）
);
CREATE TABLE messages (
  id INTEGER PRIMARY KEY AUTOINCREMENT, session_id TEXT NOT NULL,
  role TEXT NOT NULL, content TEXT NOT NULL, tokens INTEGER,
  pruned INTEGER NOT NULL DEFAULT 0,  -- 1 = 已剪枝，正文在 memory_blobs
  created_at INTEGER NOT NULL
);
CREATE TABLE memory_blobs (           -- 剪枝/压缩的原文，供 memory.fetch 恢复
  id TEXT PRIMARY KEY, session_id TEXT, message_id INTEGER,
  kind TEXT NOT NULL,                 -- tool_output / doc_chunk / early_turn
  content TEXT NOT NULL, sha256 TEXT, created_at INTEGER
);
CREATE TABLE memory_items (           -- 结构化记忆（取代旧 profile.json）
  key TEXT PRIMARY KEY, value TEXT NOT NULL,
  source TEXT, confidence REAL, updated_at INTEGER
);
CREATE TABLE terms (
  term TEXT PRIMARY KEY, starts_on TEXT NOT NULL, ends_on TEXT
);
CREATE TABLE courses (
  id INTEGER PRIMARY KEY AUTOINCREMENT, term TEXT NOT NULL, name TEXT NOT NULL,
  weekday INTEGER NOT NULL, start_period INTEGER NOT NULL, end_period INTEGER NOT NULL,
  weeks TEXT NOT NULL,                -- "1-5,7-9" / "1-16单"
  room TEXT, teacher TEXT
);
CREATE TABLE calendar_events (
  id TEXT PRIMARY KEY, title TEXT, starts_at TEXT NOT NULL, ends_at TEXT NOT NULL,
  source TEXT NOT NULL,               -- course / user / ai
  confirmed INTEGER NOT NULL DEFAULT 0, note TEXT
);
CREATE TABLE settings (key TEXT PRIMARY KEY, value BLOB);  -- 只存 keystore 引用，不存明文
```

### 5.3 云端 PostgreSQL（以 `crates/server/migrations/*.sql` 为准）

> 本节是**摘要**，不是建表脚本；字段/约束/索引的真相在迁移文件里
> （`0001_init.sql` + `0002_auth.sql`，CI 会真的在 pgvector/pg16 上跑一遍）。

```sql
CREATE EXTENSION vector;

-- 账号与设备（没有"会话正文"表）
users (id uuid pk, email text, created_at, disabled_at, password_hash);
  -- ux_users_email_lower：lower(email) 唯一
devices (id, user_id fk users, platform check in (android, windows, web),
         name, pubkey, created_at, last_seen_at);

-- 鉴权（ADR-11 / ADR-15）：只存摘要，可吊销
refresh_tokens (id, user_id fk, device_id fk, token_hash unique, expires_at, revoked_at, created_at);
access_tokens  (id, user_id fk, device_id fk, token_hash unique, expires_at, revoked_at, created_at);
  -- 过期清理走部分索引 (expires_at) where revoked_at is null

-- 授权（按时间，不按 token：ADR-03）——注意这里**没有 quotas 表**
plans       (code pk, name, valid_days > 0, price_cents >= 0, active);
entitlements(id bigserial, user_id fk, plan_code fk plans, starts_at, expires_at,
             source check in (redeem, admin, payment), created_at);
redeem_codes(code pk, plan_code fk, valid_days, used_by fk users, used_at, created_at);

-- 知识库（唯一可以放内容的地方）
knowledge_docs  (id, title, source_url, license, status check in (pending, approved, rejected),
                 created_at, updated_at);
knowledge_chunks(id bigserial, doc_id fk, ordinal, content, tsv, embedding vector(1024));
  -- ux(doc_id, ordinal) + GIN(tsv) + hnsw(embedding vector_cosine_ops)

-- 抽样用量与审计（不含正文）
usage_samples(id bigserial, user_id fk set null, turn_id, req_id, model, protocol,
              channel check in (byok, plan), round smallint, tokens_in, tokens_out,
              estimated boolean not null default false, created_at);
  -- ux_usage_user_turn_round UNIQUE (user_id, turn_id, round)：每轮一行、重放只更新（幂等）；req_id 可重复
audit_logs   (id bigserial, user_id fk set null, action, target,
              decision check in (allow, deny, error), reason, req_id, created_at);
  -- ux(action, created_at DESC) + 部分索引 (created_at DESC) WHERE decision <> 'allow'
  -- user_id 可空：鉴权失败时不知道是谁；decision=error 表示"放行后执行失败（上游问题）"
```

与早期草案的差异（避免照旧稿建表）：

| 早期草案 | 实际（W2b） | 原因 |
|---|---|---|
| `quotas` 表（tokens 余额） | **没有**；用 `entitlements`（时间段） | ADR-03：按时间授权，不按 token 记账 |
| `usage_samples.cost_cents` / `status` / `req_id unique` | **没有** `cost_cents` 与 `status`；幂等键是 `(user_id, turn_id, round)` 而不是 `req_id` | 采样表只做成本监控，不是账单；同一 turn 的多次上游调用共用 `req_id` |
| `plans.monthly_tokens` | `valid_days` + `price_cents` | 同上：卖时间不卖 token |
| 无 `access_tokens` | 有（可吊销的访问令牌，只存 SHA-256 摘要） | ADR-15：登出立即失效需要可吊销的不透明令牌 |

> 注意：**没有 `messages` 表**。会话正文不进云端（A3/T-03）。跨端同步只同步摘要与日程。

## 6. 核心流程

### 6.1 首次登录与数据导入（P3：只手动一次）

```
用户点"教务" → Flutter 打开 WebView
  → 用户在 WebView 里正常登录（我们不经手密码）
  → 登录成功后注入脚本抓取页面（课表 HTML / 成绩 JSON）
  → 通过 JS Bridge 回传原始文本给 Rust Core
  → Rust 解析 → courses/terms 落本地 SQLite
  → UI 显示"上次同步时间"
  → Cookie 由 WebView 持久化 + 导出加密副本到 keystore（供下次免登录）
```

**关键点**：不解析密码、不代理登录、不后台定时跑。同步失败只提示，不重试登录。

### 6.2 一次对话（套餐通道）

```
Flutter → Rust Core: build_context(session, user_input)
  ├ 读本地 messages + memory_items + 会话摘要
  ├ 调用 /knowledge/search（云端）拿 RAG 片段（若命中）
  ├ 估算 token，若 ≥ 55% → 压缩/剪枝，原文入 memory_blobs
  └ 产出 ChatRequest{messages, tools, budget}

Rust Core → CloudProxy → 服务端
  ├ auth（Token + 设备）
  ├ 闸门（按 turn：全局 50 + 单用户 1 + 同一 turn 去重；排队 ≤5s 后 429 + Retry-After）
  ├ 单轮上限（estimated_input_tokens > MAX_INPUT_TOKENS → 413，先拒后转不打上游）
  ├ 转发上游（reqwest/rustls；三协议适配在 core，服务端只搬请求体）
  ├ 流式回传（SSE：ChunkAssembler 装配 → meta 首、done/error 末且唯一）
  └ 收尾：1% 抽样写 usage_samples（每轮一行，`(user_id, turn_id, round)` 幂等）+ audit_logs 记 allow/deny

（W2b 未实现：余额/配额查询、Auto Review —— 见 §13 待定项与 ADR-06/ADR-03）

客户端流式渲染 → 写入 messages → 更新会话摘要
```

### 6.3 一次对话（BYOK 通道）

```
Flutter → Rust Core → DirectProvider → 模型厂商（Key 从 keystore 取，只在内存中使用）
```
差异只有三点：**服务端不参与、没有审核、没有记账**（本地仍记录 token 估算，供用户自查）。

### 6.4 上下文压缩与恢复（对应旧 Demo 的 DCP 思路）

```
token_used / token_budget ≥ 55%
  ├ 选对象：tool_output（最大） > doc_chunk > early_turn
  ├ 剪枝：保留头尾 N 行/字符，中间 → "…[已剪枝 memory://b_123，可用 memory.fetch 恢复]…"
  ├ 压缩：对更早的 1/3 轮次做摘要（用便宜模型，BYOK 用其自身 Key）
  ├ 原文整段写入 memory_blobs
  └ 上下文只留摘要 + 指针
恢复：模型调 memory.fetch(id) 或用户点"展开原文" → 从 SQLite 取回
```

**为什么原文要留**：剪枝的目的是省 token，不是丢信息。留原文才能保证"AI 忘了但能查回来"。

### 6.5 RAG 入库与检索

```
入库：文档 → 审核（非隐私）→ 解析 → 分块(512/重叠64) → embedding → chunks + tsv
检索：query → 向量 top20 + 全文 top20 → 融合(RRF) → rerank top5 → 返回带 doc/chunk id
注入：上下文里以 "[K:doc#chunk] 摘要" 形式出现；回答必须带引用
```

### 6.6 日历导出

```
terms + courses + calendar_events
  → 按学期展开为具体日期实例（Asia/Shanghai）
  → 生成 ICS（VEVENT + RRULE 可选，含 UID 稳定哈希）
  → 分享/保存到文件
```
`UID` 用 `sha1(term / name / weekday / start_period / room)`，保证重复导入不产生重复事件。

## 7. ModelGateway（双通道核心抽象）

```rust
trait ModelGateway {
    fn chat_stream<'a>(&'a self, request: &'a ChatRequest,
                       on_chunk: &'a mut (dyn FnMut(Chunk) -> Flow + Send)) -> GatewayFuture<'a>;
    fn goes_through_cloud(&self) -> bool;
}
├── DirectProvider { protocol, base_url, model }      // BYOK：端侧直连（Key 不出端）
└── CloudProxy     { base_url, access_token }         // 套餐：走服务端代理（只持时效令牌）
```

实现要点（`crates/core/src/gateway/`）：回调用 `Flow::Continue / Flow::Stop` 表达"继续 / 立刻停"；
每次调用返回 `StreamOutcome { usage, finish, cancelled, request_id }`，**记账只读 `usage`**
（装配后的终值，不要逐事件累加）；`collect_chunks()` 是给测试与 bench 的便捷函数。
`Meta` 注入 / `Done` 去重 / `usage` 合并**一律交给 `ChunkAssembler`**（§7.3），端云不各写一份。

超时分三段、**不设总时长**：建连 10s / 首事件 90s（推理模型常要 30~60s 才吐第一个 token）/
事件间空闲 30s（每收到字节重置）；`Timeouts` 可注入，测试里调小。

取消：回调返回 `Flow::Stop` 或调用方 drop 掉 future（服务端则是客户端断开）→ 立刻停止读取上游。
**准确说法**：`reqwest`/`hyper` 在响应体被 drop 后**停止读取但不会主动发 FIN**，连接由上游超时
或写完回收；成本上等价于"不再产生新的 token 消费"，不是"TCP 立刻断开"。
（删掉手写传输层、改用 reqwest 后实测确认过这一点。）

### 7.1 三协议归一化

| 关注点 | OpenAI Completions | OpenAI Responses | Anthropic Messages |
|---|---|---|---|
| 端点 | `/v1/chat/completions` | `/v1/responses` | `/v1/messages` |
| 系统提示 | `messages[0].role=system` | `instructions` | 顶层 `system` |
| 工具声明 | `tools[].function` | `tools[]` | `tools[].input_schema` |
| 流式增量 | `choices[].delta` | `response.output_text.delta` | `content_block_delta` |
| 文本 + 工具同轮（C1） | 同一 assistant 消息的 `content` 与 `tool_calls[]` 并存 | 文本 item 与每个 `function_call` item 并存 | `text` block 与多个 `tool_use` block 并存 |
| 用量 | 末帧 `usage` | `response.completed.usage` | `message_start` + `message_delta` |
| 结束原因 | `finish_reason` / `[DONE]` | `status`（`completed` / `incomplete`） | `stop_reason` / `message_stop` |
| 一事件多 Chunk（C6） | `finish_reason` + `usage` 同帧 → `[Usage, Done]` | `response.completed` → `[Usage, Done]` | `message_delta` → `[Usage, Done]` |
| 并行调用归位（C9） | `choices[].delta.tool_calls[].index` | `output_index` | `content_block_start.index` |
| 归一化后 | ⇒ 内部统一 `Chunk::Delta / ToolCall / Usage / Done`（另有 `Meta` / `ToolResult` / `Error` / `Ping`）；`parse_events` 返回 `Vec<Chunk>`，`Done` 必末 | 同左 | 同左 |

上层（上下文装配、UI 渲染、记账）只看归一化结构，**协议差异不外泄**。
内部契约的三处 P0 缺口（C1 一条消息「边说边调工具」、C6 一个事件多个 `Chunk`、
C9 并行调用缺少序号）已在 [ADR-16](04-ADR.md) / [ADR-17](04-ADR.md) 补齐；
`usage` 的多事件分片按字段取 max 合并（见 `Usage` 类型注释）。
`[DONE]` 是幂等收尾标记（Completions 会在 `finish_reason` 帧之后再来一次），
`Meta` 注入、`Done` 去重与 `usage` 合并由 `shared::stream::ChunkAssembler` 统一实现（§7.3）。

### 7.2 计费口径

1. **按时间授权、不按 token 记账**（ADR-03）：套餐卖的是"有效期"，不是 token 余额；
2. 上游返回的 `usage` 只用于**成本监控**：每个 turn **1% 抽样**，**每轮（每次上游调用）写一行**
   `usage_samples`（`(user_id, turn_id, round)` 唯一，重放只更新那一行；`channel` 区分 `byok` / `plan`；
   BYOK 也记，因为它同样花用户的 key 钱）；
3. 缺 `usage` 时用同一个 tokenizer（`core::context::estimate_tokens`）估算并把 `estimated=true` **落库**，
   这样「真的 0」和「拿不到」能区分开。**注意服务端口径比端侧粗**：不计 `tool_calls.arguments`、
   输出按 64KB 截断，仅用于成本监控，**不作为计费依据**；抽样表里**没有** `cost_cents`
   字段——真实成本靠厂商账单回归；
4. 抽样写库失败**不影响流**（fire-and-forget + `warn`）；无数据库模式下静默跳过。

### 7.3 审计事件口径

`audit_logs.decision` 三值语义：

| 值 | 含义 |
|---|---|
| `allow` | 我们放行 |
| `deny` | 按策略拒绝（鉴权失败、闸门拒绝、配额） |
| `error` | 放行后执行失败（上游超时/非 2xx/非 SSE/流中断/厂商错误帧） |

上游抖动记 `error` 而不记 `deny`，否则"被拒绝率"这类指标会被上游故障污染。

三类必记事件与 `reason` 短码：

| 事件 | action | decision | reason |
|---|---|---|---|
| 鉴权失败 | `auth.authenticate` | `deny` | `token_invalid` / `token_expired` / `user_forbidden`（`user_id` 可空） |
| 闸门拒绝 | `chat.stream` | `deny` | `turn_in_flight` / `user_in_flight` / `global_busy` |
| 上游失败 | `chat.stream` | `error` | `upstream_timeout` / `upstream_unavailable` / `upstream_status_<code>` / `upstream_protocol` / `upstream_error_frame_<code>` |

两条硬规则：**完全没带令牌的请求不落审计**（否则等于给攻击者免费的写放大，只走 tracing）；
上游失败的 `reason` 只放短码，**绝不放厂商原文**。

### 7.3 装配器（唯一的不变量实现）

`shared::stream::ChunkAssembler`：`feed(Vec<Chunk>) -> Vec<Chunk>`、`finish() -> Vec<Chunk>`、
`usage() -> Usage`。语义见 `docs/03` §9.4；端侧网关与服务端代理都只用它，不各写一份去重逻辑。

## 8. 并发与容量设计

### 8.1 分层容量

| 层 | 1000 在线时的量 | 设计 |
|---|---|---|
| 连接层（SSE） | 1000 长连接 | axum/tokio 单机足够；15s 心跳；连接池 + 超时清理 |
| 生成层 | 峰值 50 并行 | **全局信号量 50**；每用户 1；超出排队 ≤ 5s 后 429 |
| 知识检索 | QPS 峰值 ~200 | PG 向量索引 + 结果缓存（Redis 可选，1.0 先 PG 缓存表） |
| 存储 | 会话在端侧 | 云端只有用量与知识，PG 压力小 |

### 8.2 降级链

```
主模型超时(>30s) → 备用模型(同协议另一家) → 仅知识检索回答 → 明确错误
审核超时(>300ms) → 放行 + 记 log（不阻塞用户体验）
知识库不可用 → 跳过 RAG，回答里不出现引用（不能编造引用）
```

### 8.3 成本模型

```
成本/轮 = (tokens_in × 输入单价 + tokens_out × 输出单价) × k   // k≈1.15（重试+审核+压缩）
月成本  = 日活 × 轮/人/日 × 成本/轮 × 30
```
接入真实账单后回填 [01-产品需求文档 §7.2](01-产品需求文档.md)，并把 `单轮输入上限 32K` 写进配额表。

## 9. 安全设计

| 面 | 措施 |
|---|---|
| 传输 | 全链路 TLS；客户端证书固定（可选，防中间人） |
| 凭据存储 | Cookie/Key → OS 安全存储；内存中用完即清；禁止落盘明文、禁止进日志 |
| 认证 | 短期 access token（15min）+ refresh（30d）+ 设备绑定；refresh 轮换 |
| 越权 | 所有资源查询强制 `user_id` 过滤；不存在"按 id 直接取" |
| 权限 | 能力白名单（A4）；高风险动作二次确认；正则兜底粗筛（**不作为主防线**） |
| 审核 | 套餐通道 Auto Review（规则 + 小模型）；记录 decision 与 reason |
| 日志 | 结构化 + 字段级脱敏；正文只记 hash 与长度 |
| 供应链 | 依赖锁定（Cargo.lock / pubspec.lock）、`cargo audit`、构建可复现 |
| 合规 | 不存密码、可导出删除、隐私政策可读、学校数据仅用用户自己的会话 |

## 11. 部署与打包

| 端 | 产物 | 说明 |
|---|---|---|
| Android | `.aab` / `.apk` | `flutter build appbundle --release`；Rust core 交叉编译（NDK） |
| Windows | `.msix` / `.exe` | `flutter build windows`；Rust core 静态链接 |
| Web | 静态资源 | `flutter build web`，挂在服务端 `/`；只放开基础功能 |
| 服务端 | 单二进制 + 容器 | `scratch`/`distroless` 镜像；环境变量注入配置 |
| 数据库 | PG 16 + pgvector | 托管或自建；迁移用 `sqlx migrate` |

**环境变量（服务端，以 `crates/server/src/config.rs` 为准）**

| 变量 | 默认 | 作用 |
|---|---|---|
| `DATABASE_URL` | 空（无数据库模式） | PostgreSQL；不设则降级为内存鉴权 + 跳过记账 |
| `YUNONG_BIND` | `127.0.0.1:8080` | 监听地址 |
| `DB_MAX_CONNECTIONS` | 10 | 连接池大小 |
| `CONCURRENCY_LIMIT` | 50 | 全局在途 turn 上限 |
| `CONCURRENCY_QUEUE_MS` | 5000 | 全局档位排队上限，超时 → 429 |
| `MAX_INPUT_TOKENS` | 32000 | 单轮输入上限（先拒后转） |
| `SSE_HEARTBEAT_SECS` | 15 | 空闲心跳间隔，0 = 关 |
| `USAGE_SAMPLE_PERCENT` | 1 | `usage_samples` 抽样百分比 |
| `UPSTREAM_BASE_URL` / `UPSTREAM_API_KEY` | 空 | 套餐通道上游与 Key（三协议共用时的回退值） |
| `UPSTREAM_<协议>_URL` / `_KEY` | 空 | 按协议覆盖：`COMPLETIONS` / `RESPONSES` / `MESSAGES` |
| `UPSTREAM_CONNECT_TIMEOUT_SECS` | 10 | 建连（含 TLS 握手） |
| `UPSTREAM_FIRST_EVENT_TIMEOUT_SECS` | 90 | 首事件（含响应头）预算 |
| `UPSTREAM_IDLE_TIMEOUT_SECS` | 30 | 事件之间空转上限；**不设总时长** |

上游 Key 只从环境变量/密钥管理读，进 `UpstreamProvider` 的 `Debug` 会被抹成 `<redacted>`。
`REVIEW_MODEL` / `OTEL_EXPORTER` 属于 Auto Review 与指标（W2b 未实现），如今不在部署配置里。
取值与注释以 [`deploy/.env.example`](../deploy/.env.example) 为准（`deploy/docker-compose.yml` 逐项透传）。


---


**升级顺序（重要）**：新版本启动时会校验 `usage_samples` 是否具备 `turn_id` / `estimated`
（`accounting::verify_schema`）。缺失就**拒绝启动**并打印"请先执行 `migrations/0003_usage_turn_estimated.sql`"。
所以升级部署必须**先跑迁移、再起新二进制**——被自检挡下是预期行为，不是故障；无数据库模式下跳过自检。

yunong/
