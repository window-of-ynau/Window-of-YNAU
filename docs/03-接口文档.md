# 云农之窗 · 接口文档（API v1.0）

| 项 | 内容 |
|---|---|
| 文档版本 | **v1.0**；旧 Demo 的 15 个接口见 [v0-审计/03-接口文档.md](v0-审计/03-接口文档.md) |
| 契约来源 | `shared/` Rust 类型 + 生成的 JSON Schema（本文档为人工说明，**以 Schema 为准**） |
| 范围 | ① 云端 HTTP（套餐/知识/用量）② 端侧本地接口（Rust Core）③ WebView 桥 ④ 三协议适配内部契约 |

> **两条边界先记住**
> 1. **BYOK 的模型请求不经过我们**：客户端直连厂商，本文只描述"我们自己的接口"。
> 2. **会话正文不上云**：云端接口收到的 `messages` 只在内存中转发，不落库（见 [设计文档 ADR-04](02-系统设计文档.md)）。

> **W2b 实现状态**（以代码为准，本节随实现推进更新）
>
> - **已实现**：§2.1~2.4 认证、`GET /me`、`GET /healthz` `/readyz`、§3.2 `POST /chat/stream`（含 turn 闸门、SSE 代理、1% 抽样记账与审计）。
> - **仍是设计稿（未实现）**：§3.1 `GET /providers`、§3.3 `GET /chat/{request_id}`、§3.4 的 `DELETE /chat/turns/{turn_id}` 与按轮幂等、第 4~5 章（知识库 / 授权与用量查询）、Auto Review。
> - 未实现的路由直接 `404`；不要按本文直接对接这几节。

## 1. 通用约定

| 项 | 规定 |
|---|---|
| Base URL | `https://api.<domain>/api/v1`（本地 `http://127.0.0.1:8080/api/v1`） |
| 版本 | 路径版本 `/api/v1`；破坏性变更才升 v2 |
| 编码 | UTF-8；`application/json; charset=utf-8` |
| 时间 | RFC3339 UTC（`2026-10-31T09:52:40Z`），客户端负责转本地时区 |
| 鉴权 | `Authorization: Bearer <access_token>`；`/healthz` `/readyz` `/auth/*` 除外 |
| 追踪 | 响应头 `X-Request-Id`；请求可带 `X-Request-Id` 由服务端回显 |
| 幂等 | 金额/发码类接口需 `Idempotency-Key`（1.1 支付起） |
| 限流头 | `429` 带 `Retry-After`（秒，W2b 已实现）；`X-RateLimit-Remaining` / `X-Quota-Tokens-Remaining` 属 1.1 配额体系，尚未实现 |
| 分页 | `?limit=` (≤100) + `?cursor=`；响应 `next_cursor`（不透明字符串） |

### 1.1 成功响应

```json
{ "ok": true, "data": { }, "request_id": "req_9f3c" }
```

### 1.2 失败响应

```json
{
  "ok": false,
  "error": {
    "code": "QUOTA_EXCEEDED",
    "message": "本月配额已用完，可升级套餐或改用自带 Key",
    "request_id": "req_9f3c",
    "details": { "remaining": 0, "reset_at": "2026-11-01T00:00:00Z" }
  }

```

### 1.3 错误码总表

| code | HTTP | 含义 | 客户端动作 |
|---|---|---|---|
| `UNAUTHORIZED` | 401 | 无/过期 token | 刷新 token，失败则登录 |
| `TOKEN_EXPIRED` | 401 | access 过期（可区分） | 用 refresh 换新 |
| `FORBIDDEN` | 403 | 越权 | 提示无权限 |
| `NOT_FOUND` | 404 | 资源不存在 | 回到列表 |
| `VALIDATION_ERROR` | 422 | 参数非法 | 提示字段 |
| `MESSAGE_TOO_LARGE` | 413 | 超单轮上限 | 提示压缩/分次 |
| `CONCURRENCY_LIMIT` | 429 | 已有在途请求 | 等待/取消旧的 |
| `RATE_LIMITED` | 429 | 频率超限 | 按 `Retry-After` 重试 |
| `QUOTA_EXCEEDED` | 402 | 配额耗尽 | 引导升级/换 BYOK |
| `REVIEW_REJECTED` | 403 | Auto Review 拒绝 | 展示 reason，不建议重试 |
| `UPSTREAM_TIMEOUT` | 504 | 上游超时 | 可重试一次 |
| `UPSTREAM_ERROR` | 502 | 上游错误（含未配置上游） | 可重试；连续失败引导换模型 |
| `NOT_IMPLEMENTED` | 501 | 骨架期占位 | **W2b 已无接口返回它**（`/chat/stream` 已是真实转发）；保留给 1.1 未实现的功能 |
| `INTERNAL` | 500 | 未捕获 | 展示 request_id |

## 2. 认证

> **令牌形态：不透明串，不是 JWT**（[ADR-15](04-ADR.md)）。
> 客户端拿到的 64 位十六进制串，服务端只存它的 SHA-256；因此：**登出立刻失效、可吊销、可设备绑定**，
> 也不需要维护签名密钥。代价是每次请求多一次令牌表查询（1000 人在线量级可忽略）。

### 2.1 `POST /auth/register`

```json
{ "email": "a@b.com", "password": "***", "invite_code": "YNAU-2026" }
```
→ `201 data: { "user_id": "uuid", "access_token": "...", "expires_in": 900, "refresh_token": "..." }`

### 2.2 `POST /auth/login`

```json
{ "email": "a@b.com", "password": "***", "device": { "platform": "android", "name": "Pixel 8" } }
```
→ `200 data: { access_token, expires_in, refresh_token, user }`

### 2.3 `POST /auth/refresh`

```json
{ "refresh_token": "..." }
```
→ `200 data: { access_token, expires_in, refresh_token }`（**refresh 轮换**，旧 token 立即失效）

### 2.4 `POST /auth/logout`
→ `200 data: { "ok": true }`（吊销当前 refresh）

## 3. 模型与对话

### 3.1 `GET /providers`

返回可用的模型与协议组合（**不含任何 Key**；BYOK 用户据此渲染下拉框）。

```json
{
  "ok": true,
  "data": {
    "protocols": ["openai_completions", "openai_responses", "anthropic_messages"],
    "models": [
      { "id": "deepseek-chat", "protocol": "openai_completions", "context": 128000, "channels": ["byok", "plan"] },
      { "id": "claude-x", "protocol": "anthropic_messages", "context": 200000, "channels": ["byok"] }
    ]
  }
}
```

> BYOK 用户还可以在设置里填**自定义 Base URL + 模型名**，服务端不做白名单限制（我们不经手其流量）。

### 3.2 `POST /chat/stream`（套餐通道，主接口）

**请求**

```json
{
  "session_id": "s_123",
  "turn_id": "t_88",
  "round": 1,
  "model": "deepseek-chat",
  "protocol": "openai_completions",
  "messages": [
    { "role": "system", "content": "..." },
    { "role": "user", "content": "下周三下午有课吗" }
  ],
  "tools": [ { "name": "get_courses", "parameters": { } } ],
  "max_output_tokens": 1024,
  "stream": true,
  "estimated_input_tokens": 3120
}
```

| 字段 | 说明 |
|---|---|
| `session_id` | 端侧生成，服务端只用于日志串联，**不落库** |
| `turn_id` | **一次用户提问**的唯一 id；多轮工具循环共享它，**并发闸门按 turn 计，不按 HTTP 请求计**（否则第 2 轮被自己第 1 轮的闸门挡住） |
| `round` | 第几轮（1..=`MAX_ROUNDS`，当前 4）；`round=0` 或 `>4` 直接 `422 VALIDATION_ERROR`（见 §3.4） |
| `messages` | 端侧装配好的完整上下文，**必须 append-only**（见 §3.4） |
| `tools` | 工具声明（端侧提供，服务端原样转发，**从不执行**） |
| `estimated_input_tokens` | 端侧估算，用于**先拒后转**（超额直接 413，不产生上游费用） |

**响应**：`200 text/event-stream`

```
event: meta
data: {"type":"meta","request_id":"req_9f3c","model":"deepseek-chat","channel":"plan"}

event: delta
data: {"type":"delta","text":"下周三下午"}

event: tool_call
data: {"type":"tool_call","id":"c1","name":"get_courses","arguments":{"weekday":3,"week":9},"index":0}

event: usage
data: {"type":"usage","tokens_in":3120,"tokens_out":96,"estimated":false}

event: done
data: {"type":"done","finish":"stop"}
```

**规则**

- **并发闸门按 turn 计**（W2b 已实现，见 `crates/server/src/gate.rs`）：
  - 全局最多 `CONCURRENCY_LIMIT`（默认 50）个在途 turn；满档时**排队**（`CONCURRENCY_QUEUE_MS`，默认 5000ms），排队超时 → `429 CONCURRENCY_LIMIT`；
  - 单用户同时只允许 1 个在途 turn，第二个立即 `429`（等也没意义，客户端该先取消旧的）；
  - 同一 `turn_id` 在途时重复提交 → `429`（`Retry-After: 1`）。
- **客户端断开** → 服务端**立即停止读取上游**，不再消费新的 token；TCP 连接不会立刻 FIN（`reqwest`/`hyper` 的行为），由上游超时或写完回收——所以成本上等价于"停止生成"，但不是"立刻断开"。名额与抽样记账在任务收尾时处理。
- **心跳**：上游连续 15s 没有数据时下发一条 `event: ping`（`SSE_HEARTBEAT_SECS=0` 可关）——有数据时不心跳，避免刷屏。
- **上游错误映射**（全部走统一错误信封）：上游超时 → `504 UPSTREAM_TIMEOUT`；连不上/非 2xx/响应不合法 → `502 UPSTREAM_ERROR`。其中「响应不合法」**包括 2xx 但 `Content-Type` 不是 `text/event-stream`**（例如被中间层换成登录页或非流式 JSON）——这种情况绝不产出 `Meta+Done` 的"空回答"。对外**只给错误码 + 固定文案**（504「上游响应超时，请稍后重试」/ 其余 502「上游暂时不可用，请稍后重试」）：内网地址、环境变量名、上游原文只进服务端日志。请求体的 `stream` 由服务端强制为 `true`（客户端传不传都一样）。服务端会把这类上游失败记入审计（`audit_logs.decision = error`，不记 `deny`——它不是"我们拒绝了用户"）。**已经开流之后**上游帧里带的厂商 `error` 同样清洗：`event: error` 里只有错误码 + 固定文案，厂商原文只进服务端日志。
- **Auto Review 未实现**（ADR-06 仍是设计）：`REVIEW_REJECTED` 这条路径 W2b 不会出现，1.1 再补。

### 3.3 `GET /chat/{request_id}`（可选，1.1）
用于断线后查询该次调用是否已完成（**不返回内容**）。

### 3.4 工具循环（多轮，见 [ADR-05](04-ADR.md)）

模型返回 `tool_call` 时，**客户端执行工具**，然后以同一 `turn_id`、`round+1` 再发一次请求；`messages` 末尾追加 `assistant(tool_call)` 与 `tool(tool_result)`。

```
round 1: user ──▶ [stream] ──▶ tool_call(get_courses)
round 2: + tool_result ──▶ [stream] ──▶ delta … done
```

| 约束 | 说明 |
|---|---|
| **最多 4 轮** | `ChatRequest::validate` 在 `round=0` 或 `round>MAX_ROUNDS`（4）时直接 `422 VALIDATION_ERROR`，不打上游。契约里的 `finish="max_rounds"`（`FinishReason::MaxRounds`）预留给**端侧编排**收尾，W2b 尚无产出方（1.1） |
| **append-only** | 只在末尾追加；**禁止重排、禁止中途压缩**——否则厂商 prompt cache 失效，成本翻倍。压缩只在一轮结束时做 |
| **按轮幂等（1.1）** | 设计上 `(user_id, turn_id, round)` 唯一、重复提交返回同一 `request_id`。**W2b 未实现**：当前只保证"同一 turn 在途时重复提交 → `429`"；turn 结束后重提是新 `request_id`、会真的再打一次上游 |
| **并发按 turn 计** | 每个请求占 1 个并发名额，**流结束即释放**；同一 `turn_id` 在途重复提交直接 429（实现里 permit 在 turn 结束时 `drop`，不做轮次间保留；W3 工具多轮时重新评估） |
| **工具不执行** | 服务端只转发 `tools` 与 `tool_result`，不解析、不执行、不缓存 |

取消（W2b）：只有一条路——**客户端关闭连接**（服务端立即停止读上游并释放名额）。
`DELETE /chat/turns/{turn_id}`（中止剩余轮次）**1.1 才做**，现在没有这个路由。

## 4. 知识库（RAG）

### 4.1 `POST /knowledge/search`

两条通道都用这个接口（ADR-05）。

```json
{ "query": "云南农业大学 转专业 条件", "top_k": 5, "filters": { "doc_type": "regulation" } }
```

```json
{
  "ok": true,
  "data": {
    "chunks": [
      { "id": "c_88", "doc_id": "d_7", "title": "本科生转专业管理办法",
```

→ `201 { "doc_id": "d_7", "status": "pending" }`（需审核通过才可检索）

## 5. 授权时效与成本监控

> **计费模型：按时间授权，不按 token 记账**（[ADR-03](04-ADR.md)）。
> token 只做 **1% 抽样**，用途是**成本监控与熔断**，不用于计费；因此这张表里没有"余额"，只有"有效期"。

### 5.1 `GET /quota`

```json
{ "ok": true, "data": {
  "channel": "plan",
  "plan": "plan_30d",
  "entitlement_expires_at": "2026-11-30T00:00:00Z",
  "concurrent_limit": 1,
  "max_input_tokens": 32000,
  "knowledge_rpm": 30,
  "sampled_cost_cents_7d": 12 } }
```

- `channel`：`plan`（代理）/ `byok`（直连，此接口只返回 `knowledge_rpm` 等公共项）；
- `sampled_cost_cents_7d`：近 7 天抽样成本估计，仅用于"给你自己看的账单感"。

### 5.2 `GET /usage?period=day|month`

```json
{ "ok": true, "data": {
  "period": "month", "sampled": true, "sample_rate": 0.01,
  "est_tokens_in": 812000, "est_tokens_out": 96000,
  "est_cost_cents": 240,
  "records": [ { "req_id": "req_9f3c", "model": "deepseek-chat",
                 "tokens_in": 3120, "tokens_out": 96, "round": 1,
                 "created_at": "2026-10-31T09:52:40Z" } ],
  "next_cursor": null } }
```

> **`sampled: true` 是刻意的**：这不是账单，是监控样本。别把抽样数字当计费依据写进 UI。

### 5.3 `GET /plans`

```json
{ "ok": true, "data": [ { "code": "plan_30d", "name": "30 天不限量", "valid_days": 30, "price_cents": 990 } ] }
```

### 5.4 `POST /redeem`

```json
{ "code": "YNAU-ABCD-1234" }
```
→ `200 data: { "plan": "plan_30d", "valid_days": 30, "entitlement_expires_at": "2026-11-30T00:00:00Z" }`
错误：`NOT_FOUND`（无效码）、`FORBIDDEN`（已被使用）。

### 5.5 成本熔断（服务端内部，无对外接口）

```
每小时扫描抽样成本：
  cost_user > 20 × 均值   → 临时限流 + 告警（不封号，先看）
  cost_global > 阈值      → 收紧全局闸门（50 → 30），并通知管理员
```

## 7. 端侧本地接口（Rust Core）

> 不是 HTTP，是 `flutter_rust_bridge` 暴露的异步函数。Dart 侧只看到这些签名；**所有敏感数据在这层以下**。

### 7.1 凭据

```rust
// 返回值只返回引用是否存在，不返回值本身
set_secret(kind: SecretKind, value: String) -> Result<()>      // kind: ApiKey | SchoolCookie
has_secret(kind: SecretKind) -> Result<bool>
```

### 7.5 课表（C ABI，W6 已实现）

导出面（`crates/core/src/ffi.rs`），全部返回 JSON 信封 `{ok,data}` 或 `{ok:false,code,message}`：

```c
const char *yunong_core_version(void);
char *yunong_import_timetable(const char *html, const char *term, const char *db_path);

```

错误码：`BAD_INPUT`（入参非法）/ `PARSE_FAILED`（页面改版）/ `PARSE_EMPTY`（解析出 0 门课）/

课表 HTML 由 WebView 抓取（见 §8.3），端侧只接受 HTML 文本、不接触 Cookie；
空解析结果报错且**不清库**。日历（周次展开、日程增删、ICS 导出）属 W9，尚未实现。

## 8. WebView JS Bridge（校务取数）

> 只在 App 内部，不过网络。目的：把"用户自己的会话"变成结构化数据。

### 8.1 消息格式

```json
{ "v": 1, "type": "timetable", "page_url": "https://...", "captured_at": 1761923560,
  "html": "<table id=\"timetable\">…</table>" }
```

| type | 载荷 | 说明 |
|---|---|---|
| `login_done` | 无 | 检测到已登录（URL/元素特征） |
| `timetable` | `html` | 课表页 HTML，端侧解析 |
| `score` | `json` | 成绩接口 JSON（若页面本身是 XHR 渲染，则注入 hook 取） |
| `exam` | `html` | 考试安排 |
| `error` | `{code, message}` | 抓取失败（未登录/网络/页面改版） |

### 8.2 端侧解析产物

```json
{ "term": "2026-2027-1",
  "courses": [ { "name": "高等数学A", "weekday": 1, "start_period": 1, "end_period": 2,
```

### 8.3 登录流程与会话（W6）

```text
点「登录并抓取课表」
  → 打开课表页
       ├─ 会话有效：直接是课表页 → 探针看到 table#timetable → 自动抓取
       └─ 会话失效：CAS 跳到统一身份认证 → 用户登录（验证码/二次验证）
                      → 跳回课表页 → 探针看到业务元素 → 自动抓取（无需再点按钮）
  → 取 table#timetable 的 outerHTML → bridge 回传 → 关闭 WebView
  → 端侧解析 → SQLite（terms/courses）→ 列表
```

**会话存放位置**（Cookie 只在本机）

| 平台 | 位置 | 说明 |
|---|---|---|
| Windows | `%LOCALAPPDATA%\yunong\webview\`（WebView2 user data folder） | 必须在创建 WebView **之前**指定；放临时目录等于每次重启都要重新登录 |
| Android | 应用私有目录（系统 CookieManager 管理） | 需开启 `thirdPartyCookiesEnabled`（CAS 与业务系统不同域），否则会出现"登录成功但业务页仍未登录" |

Cookie **不进** SQLite / JSON / 日志，不上传；端侧从不读 `document.cookie`。

**登录态判定**（只观察 DOM 与可见文本）

| 优先级 | 信号 | 判定 | reason |
|---|---|---|---|
| 1 | `table#timetable` / `table.timetable` / `#timetable` | 已登录 | `timetable` |
| 2 | `#xh_id` / `.user-info` / `.stu-name` / `#topMenu`，或可见文本 `学号：\d{6,}`、`姓名：…` | 已登录 | `student_bar` |
| 3 | iframe 内出现课表表格（同域可读） | 已登录 | `timetable_iframe` |
| 4 | `input[type=password]` / `#casLoginForm` / `form[action*="login"]` | 需登录 | `login_form` |
| 5 | 可见文本「请登录 / 未登录 / 登录超时 / 重新登录」 | 需登录 | `login_hint` |
| — | 均无 | 未知，提示页面可能改版 | `no_signal` |

不以 URL 判定：CAS 在教务、统一身份认证之间反复跳转，URL 变化既不代表成功也不代表失败。
上报的 `path` 去掉 query 与 fragment（CAS 的 `ticket` 属凭据）。

**抓取失败码**

| code | 触发 | 用户可见提示 |
|---|---|---|
| `HTML_CHANGED` | 自动重试约 30s 后仍找不到 `table#timetable` | 学校页面可能已更新，请反馈 |
| `LOGIN_TIMEOUT` | 5 分钟内未完成登录或未抓到 | 登录超时，请重试 |
| `NETWORK` | 解析失败 / 超时 / 连接失败 | 校务系统打不开，请检查校园网 |
| `CERT` | 证书错误 | 校务系统证书异常，请检查网络环境 |
| `NO_WEBVIEW` | 平台无内嵌浏览器 | 当前平台不支持内置浏览器 |
| `CANCELLED` | 用户取消 | 已取消抓取 |

**不变量**：抓取或解析失败绝不写入空课表、绝不清空已有列表。
## 9. 三协议归一化契约（内部）

> 真相在 `crates/shared/src/protocol.rs`，本节只是摘要。W2b 补齐两处 P0 缺口：
> **C1** = 一条消息可以「边说边调工具」+ 并行多调用，**C6** = 一个上游事件可以产出多个
> `Chunk`（[ADR-16](04-ADR.md)）。

```rust
struct ChatRequest {
    session_id: String, turn_id: String, round: u8,
    model: String, protocol: Protocol,      // openai_completions | openai_responses | anthropic_messages
    messages: Vec<ChatMessage>, tools: Vec<ToolSpec>,
    max_output_tokens: u32, stream: bool, estimated_input_tokens: u32,
}
struct ChatMessage {
    role: Role,                      // system | user | assistant | tool
    content: String,                 // 只有可见文本
    tool_call_id: Option<String>,    // role=tool 必填
    name: Option<String>,            // 可选，便于日志与调试
    tool_calls: Vec<ToolCallRef>,    // C1：assistant「边说边调工具」+ 并行多调用
}
struct ToolCallRef { id: String, name: String, arguments: serde_json::Value }

// Chunk 是**对外 SSE 的 wire 形状**：`#[serde(tag = "type")]`，事件名由 `Chunk::event_name()` 给
enum Chunk {
    Meta { request_id: String, model: String, channel: Channel },          // 必首且唯一
    Delta { text: String },
    ToolCall { id: String, name: String, arguments: serde_json::Value,
               index: Option<u32> },                                       // C9；None 时**不序列化**
    ToolResult { id: String, ok: bool, content: String },                  // 端侧回填（第 2 轮请求里出现）
    Usage { tokens_in: u32, tokens_out: u32, estimated: bool },            // 0 = 本事件未携带该字段
    Done { finish: FinishReason },  // stop | length | tool_calls | max_rounds | error；必末且唯一
    Error { code: ErrorCode, message: String },                            // 终止事件（随后关闭连接）
    Ping,
}
```

| 归一化字段 | Completions | Responses | Messages |
|---|---|---|---|
| 系统提示 | `messages[0]` | `instructions` | `system` |
| 工具 | `tools[].function` | `tools[]` | `tools[].input_schema` |
| 文本增量 | `choices[0].delta.content` | `output_text.delta` | `content_block_delta`（`text_delta`） |
| 工具增量 | `delta.tool_calls[]`（一个 delta 可含多个） | `function_call_arguments.delta` | `input_json_delta` |
| 结束原因 | `finish_reason` | `status`（`completed` / `incomplete`） | `stop_reason` |
| 用量 | 末帧 `usage` | `response.completed.usage` | `message_start` + `message_delta` |

### 9.1 一个事件可以产出多个 `Chunk`（C6）

`parse_events(protocol, data) -> Vec<Chunk>`。三协议的"结束原因 + usage"经常挤在同一事件里，
旧的一事件一 Chunk 必然二选一（丢 token 数 = 成本监控失真）：

| 协议 | 同事件案例 | 产出 |
|---|---|---|
| Completions | 末帧同时有 `finish_reason` 与 `usage` | `[.., Usage, Done]` |
| Messages | `message_delta` 同时有 `stop_reason` 与 `usage.output_tokens` | `[Usage, Done]` |
| Responses | `response.completed`（**唯一**终态**且**唯一 usage 来源） | `[Usage, Done]` |

- 顺序不变量：`Done` 必末且唯一（见 §10）；同一事件的 `Usage` 一定排在 `Done` **之前**。
- **`[DONE]` 幂等**：Completions 的 `finish_reason` 帧已经给出带真实原因的 `Done`，
  随后还会再来一个 `[DONE]`，所以一条完整流可能给出两次 `Done`——"唯一"由 **gateway 去重**
  （首个 `Done` 为准）保证，而不是丢掉 `finish_reason`。
- 空串 / 心跳 / 非 JSON → 空 `Vec`；`[DONE]` → `[Done{Stop}]`；上游错误 → `[Error{UpstreamError}]`。
- 一个 delta 里既有文本又有工具调用（Completions 常见）→ `[Delta, ToolCall]`，不再二选一。

### 9.2 `usage` 分片与合并口径（C6 配套）

`Usage.tokens_in` / `tokens_out` **为 0 表示"本事件未携带该字段"**，不是真实 0。
同一 `turn_id` 的多个 `Usage` 由 gateway / 记账层**按字段取 max 合并**
（上游累计值单调不减；Anthropic 的 input / output 是互不重叠的分片）；
任一事件 `estimated=true`，合并结果也是 `true`。

### 9.3 工具调用的表达（C1）

- assistant 的**可见文本**在 `content`、工具调用在 `tool_calls[]`，两者可以同时出现；
  只调工具不发言时 `content` 为空串（Completions 编码成 `null`）。
- 并行调用 = `tool_calls[]` 多个元素（Completions 同一数组 / Messages 多个 `tool_use` block /
  Responses 多个 `function_call` item）。
- `arguments` 永远是合法 JSON 值；聚合未完成时允许是字符串片段，由 gateway 按
  `index` / `item_id` 拼接后再整体解析。
- `Chunk::ToolCall` 带 `index: Option<u32>`（C9）：Completions 取 `tool_calls[].index`、
  Anthropic 取 `content_block_start.index` / `input_json_delta` 的 `index`、Responses 取
  `output_index`。**并行调用靠它归位**——没有序号，A 的参数会被拼到 B 上。
  `None` 时**不序列化**，老客户端与老 JSON 都不受影响。
- 结构性校验（发请求前失败，`VALIDATION_ERROR`）：`tool_calls` 只能出现在 assistant 上；
  每个调用的 `id` / `name` 非空；`role=tool` 消息必须有非空 `tool_call_id`。

> 适配器**必须**产出一致的 `Chunk` 序列；契约测试对三协议跑同一组 fixture
> （每个适配器都有"文本 + 工具同轮"与"usage + 结束原因同事件"两条）。
> `Chunk` 的字段是**对外 SSE 的 wire 形状**，不随内部类型变化：`ToolCallRef` 与
> `Chunk::ToolCall` 刻意同构但**不共用类型**。

### 9.4 装配器：不变量只实现一次（`shared::stream::ChunkAssembler`）

上游并不配合我们对外承诺的两条不变量（`Meta` 必首且唯一、`Done`/`Error` 必末且唯一），
而**端侧网关（BYOK）与服务端代理（套餐）都消费 `parse_events`**——去重与合并各写一份必然分叉。
所以只有一份实现：`yunong_shared::ChunkAssembler`（见 [ADR-16](04-ADR.md)）。

```rust
let mut asm = ChunkAssembler::new(Channel::Plan, request_id, model);
// 转发循环里：
for chunk in asm.feed(parse_events(protocol, raw_data)) { write_sse(chunk).await?; }
for chunk in asm.finish() { write_sse(chunk).await?; }   // 上游正常关闭但没给结束帧 → 补一个 Done
let usage = asm.usage();                                  // 记账只读这个终值
```

| 方法 | 语义 |
|---|---|
| `feed(Vec<Chunk>) -> Vec<Chunk>` | 首个调用先吐 `Meta`；之后重复的 `Done` / `Error` 一律丢弃（`[DONE]` 幂等）；`Error` 是终止事件，**不会**在其后补 `Done` |
| `finish() -> Vec<Chunk>` | 只在"上游正常关闭但没有终止事件"时补 `Done`，且只补一次；已有 `Error` 时返回空 |
| `usage() -> Usage` | **合并后的终值**（按字段取 max、`estimated` 取或）——`usage_samples` **每轮（每次上游调用）写一行**，`(user_id, turn_id, round)` 唯一，重放只更新那一行 |

## 10. SSE 规范（套餐通道）

| 项 | 规定 |
|---|---|
| Content-Type | `text/event-stream; charset=utf-8` |
| 缓存 | `Cache-Control: no-cache`，禁用代理缓冲（`X-Accel-Buffering: no`） |
| 事件 | `meta` `delta` `tool_call` `tool_result` `usage` `done` `error` `ping` |
| 心跳 | 上游连续 15s 无数据时下发 `event: ping`（`SSE_HEARTBEAT_SECS`，0 = 关） |
| 顺序 | `meta` 必首且唯一，`done`/`error` 必末且唯一（由 `ChunkAssembler` 保证） |
| 取消 | W2b 只有**客户端关闭连接**（服务端立即停止读上游并释放名额）；`DELETE /chat/...` 是 1.1 的设计，尚未实现 |
| 重连 | 不重放历史（内容已在端侧）；重连即新请求，需客户端去重 |
| 上游断流 | 发 `event: error`（`UPSTREAM_TIMEOUT` / `UPSTREAM_ERROR`）后关闭，**不再补 `done`** |

## 13. 兼容与弃用

1. 新增字段**不算**破坏性变更；删除/改语义才算；
