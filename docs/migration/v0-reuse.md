## 1. 课表 HTML 解析（`table#timetable`）

### 1.1 页面结构（先认清，再写解析）

旧解析器对页面的假设（`parse_schedule_time.py:145-203`）：

| 结构 | 旧代码 | 说明 |
|---|---|---|
| 课表容器 | `soup.find("table", id="timetable")`（:149） | 找不到就 `SystemExit`（:151）——**这一点做对了**，1.0 要学 |
| 星期表头行 | 任一 `tr` 含文本带"星期"的 `th`（:154-163） | 表头文字即"星期一…星期日"，**顺序**就是列顺序 |
| 节次来源 | 每行第一个 `th` 里的 `第\s*(\d+)\s*节`（:21, :178） | 该行的小节号，作为"块内丢了节次"时的 fallback |
| 列对齐 | `row.find_all("td", recursive=False)` 的**下标**与表头 `th` 下标一一对应（:183-185） | 见 R6 的列数校验 |

### 1.2 R1 — 只取 `div.kbcontent`，不取 `kbcontent1`

```
规则：单元格内容只从 td 的直接子元素 div.kbcontent 读取；
      取不到时才退回整个 td。
```

- **旧证据**：`parse_schedule_time.py:36-38`
  ```python
  cells = td.find_all("div", class_="kbcontent", recursive=False)
  if not cells:
      cells = [td]
  ```
  注释写明（:31-35）：每个格子有 `kbcontent1`（简版）和 `kbcontent`（完整版），**只解析完整版，避免同一门课被解析两次**。
- **为什么必须保留**：教务页面把同一门课同时输出成"简版 + 完整版"。两份都解析 → 课表里每门课出现两次，用户第一反应是"这个 App 数据是错的"。
- **1.0 怎么写**：`core::parse::schedule::timetable`
  - 只取 `div.kbcontent` 的**直接子元素**（`recursive=False` 语义：不要再往嵌套 div 里钻，否则祖先+后代重复取）；
  - 取不到 `kbcontent` 时用整个 `td`，但**记一条 `warn`**（说明页面结构变了，是版本漂移的信号，不是正常路径）。

### 1.3 R2 — `------` 是"同一格里多门课"的分隔符

```
规则：5 个及以上连续 "-"（夹在 <br> 之间）是分隔符；
      一个 td 可以切成 N 个独立课程块，逐个解析。
```

- **旧证据**：`parse_schedule_time.py:18, 40-45`
  ```python
  BLOCK_SEPARATOR_RE = re.compile(r"(?:<br\s*/?>\s*)?-{5,}(?:\s*<br\s*/?>)*", re.I)
  ...
  parts = BLOCK_SEPARATOR_RE.split(html)
  blocks.extend(part for part in parts if "<font" in part.lower())
  ```
- **为什么必须保留**：一格两门课（如"高等数学"+"线性代数"同一时段）是真实数据，不切块就会把两门课的名字/教师/周次串成一条垃圾记录。
- **1.0 怎么写**：
  - 分隔判定用"≥5 个 `-`"，**不要求恰好 6 个**（旧页面 6 个，写死 6 会在改版后失效）；
  - **不要**沿用 `if "<font" in part` 这种字符串探测（:44）——它是"静默丢块"的来源，见 §4.1。1.0 应改为：切出的每段都送进解析器，解析器返回 `Err(NoFontElements)` 时**计数并上报**，而不是悄悄跳过。

### 1.4 R3 — `<font title="…">` 的字段解析顺序

```
规则：按文档顺序遍历块内所有 <font>；title 决定这个 font 是什么字段；
      没有 title 的 font 且课程名未赋值 → 它是课程名。
```

- **旧证据**：`parse_schedule_time.py:94-112`

  | `title` 属性 | 映射字段 | 旧代码行为 | 备注 |
  |---|---|---|---|
  | `教师` | `教师` | `setdefault`（:100-101） | 先到先得，重复只取第一个 |
  | `周次(节次)` | `周次` + `节次` | 先用 `\[(.+?)\]` 抓出 `[01-02节]` → `节次`；再把 `[...]` 删掉，剩下的 → `周次`（:102-108） | 两个字段各自只在**首次**赋值 |
  | `教室` | `教室` | `setdefault`（:109-110） | |
  | 空 | `课程名` | 仅当尚未赋值（:111-112） | **没有 title 的 font 就是课程名** |
  | 其它 | 忽略 | 无 else 分支 | 未知 title 不报错 |

- **为什么必须保留**：这是学校模板的**客观输出格式**，不是作者的选择。字段名写错一个（比如以为是 `title="周次"`）就整套解析为空。
- **文本清洗规则**（`clean_text`，:24-27）也必须一起搬：
  ```python
  text = tag.get_text("", strip=True).replace("\xa0", "")
  return re.sub(r"\s+", " ", text).strip()
  ```
  - `get_text("")` 分隔符是**空串**：`<font>高等数学</font><b>A</b>` → `高等数学A`（不是 `高等数学 A`）；
  - 去 `\xa0`（`&nbsp;`）；
  - 折叠连续空白为单空格，但**不要删词内空格**（课程名可能带空格，如 `大学 英语`）。
- **1.0 怎么写**：`core::parse::schedule::font_fields`
  - 严格按上表实现，未知 `title` 记 `warn`（不失败）；
  - `周次(节次)` 里的 `[...]` 只截**第一对**（旧正则 `\[(.+?)\]` 非贪婪）；
  - `节次` 文本形如 `01-02节`，**别假设是两位数字**（见 R10a）；
  - 旧代码用 `"节次" not in data` / `"周次" not in data` 判断首次赋值——1.0 建议改为"重复出现且值不同 → 记 `warn`"，因为那往往意味着页面结构变了。

**反例（会直接导致整门课丢字段）**：

| 错误写法 | 后果 |
|---|---|
| 按 `title` 建 map 一次性取值，不做"首次赋值"保护 | 后出现的 `教师` 覆盖前面的 |
| 用 `font.find(text=True)` 只取第一个文本节点 | `<font>高等数学<b>A</b></font>` 丢失 `A` |
| 把 `周次(节次)` 的整段文本当周次 | 周次里混进 `[01-02节]`，解析出的周次数值里会多出 `1`、`2`，**直接制造错误的"本周有课"** |

### 1.5 R4 — 去重键必须用**规范化后**的值

```
规则：同一课程块会在每个小节行重复出现一次（rowspan 展开），
      必须按完整信息去重。
```

- **旧证据**：`parse_schedule_time.py:191-203`，键为
  `(课程名, 星期, 周次原文, 节次原文, 教室, 教师)`。
- **为什么必须保留**：不去重 → 一节大课在课表里出现 2 次（占 1-2 节的行），提醒用户时发两条。
- **旧实现的缺陷（1.0 要修）**：键里用的是**原文**（`周次`="1-16(周)"、`节次`="01-02节"）。
  同一个语义只要写法不同（`1-16周` / `1-16(周)`、`01-02节` / `1-2节`）就**去重失效**。
- **1.0 怎么写**：`core::parse::schedule::dedupe`，键用规范化后的值：
  ```
  (name, weekday: u8, start_period: u8, end_period: u8, weeks: WeekSet, room, teacher)
  ```
  其中 `weeks` 是展开后的位集合（R7-R9 的产物），不是原文。**规范化是去重的前提。**

### 1.6 R5 — 空块 / 缺关键字段的块：1.0 必须可观测

| 情况 | 旧行为 | 1.0 |
|---|---|---|
| 块内没有任何 `<font>` | 被静默丢弃（:44） | `err` + 计数（这是"页面改版"的典型信号） |
| 拿不到课程名 | 返回 `None` 丢弃（:114-115） | `err(NoCourseName)` + 计数 |
| 拿不到节次（`[节次]` 和行首 `第N节` 都失败） | 返回 `None` 丢弃（:117-119） | `err(NoPeriod)` + 计数 |

> 旧代码 `return None` 的地方一共 3 处（:114-115、:117-119，加：44 的过滤），全部是**无声的**。
> 见 §4 为什么这必须改。

### 1.7 R6 — 列数必须校验，不匹配就**失败**

```
规则：td 数量必须与表头"星期X"的数量一致；不一致 → 解析失败，不做部分解析。
```

- **旧证据**：`parse_schedule_time.py:183-185`
  ```python
  for index, td in enumerate(row.find_all("td", recursive=False)):
      if index >= len(weekdays):
          break
  ```
  超出的列被 `break` 丢掉、不足的列自然缺——**任何一侧都没有报错**。
- **为什么必须改**：表头多出"备注"列或合并单元格导致列数变化时，
  旧代码会把**整张表按错位一格**解析 —— **静默产生的错误数据比空表危险得多**（用户会按错的课表去上课）。
- **1.0 怎么写**：
  - 先算 `expected = weekdays.len()`，每行 `td.len() != expected` → `Err(ColumnMismatch { row, expected, got })`；
  - 允许的例外只有一种：整行只有一个跨列的大 `td`（`colspan == expected`），此时按"无课"处理并记 `warn`；
  - **禁止**用 `break` 兜底。

### 1.8 R7 — 星期值来自**表头顺序**，不要猜中文数字

- **旧证据**：`parse_schedule_time.py:165-169`，`weekday` 存的就是表头文本 `星期一`。
- **1.0**：`weekday: u8`，1=周一 … 7=周日，由**表头下标 + 1** 得到。
  **不要**用 `"三" → 3` 这种映射（表头可能写成 `周一`、`星期一`、带日期 `星期一 03/02`）。
  表头必须**恰好 7 个**，否则失败（少列 = 页面残缺，多列 = 结构变了）。

## 2. 周次解析（最容易丢语义的一步）

### 2.1 R8 — 规范输入形态（学校实际写法）

旧解析器要处理的写法（`parse_schedule_time.py:48-76` 的能力边界）：

| 输入 | → 周次集合 |
|---|---|
| `4-15(周)` | `{4..15}` |
| `1-5,7-9(周)` | `{1,2,3,4,5,7,8,9}` |
| `1-16单周` | `{1,3,5,7,9,11,13,15}` |
| `2-16双周` | `{2,4,6,8,10,12,14,16}` |
| `1-16(单)` | `{1,3,…,15}` |
| `第1-16周` | `{1..16}` |
| `1-16`（无括号） | `{1..16}` |
| `全角` `1-16（周）` | 与半角等价（先归一化全角括号） |

- 区间连接符的字符集：`-`、`~`、`—`、`至`（`:20` 的 `[-~—至]`）。**原样保留这个字符集**，别只支持 `-`。
- 多值分隔符：`,`、`，`、`、`、`;`、`；`、空白（`:60`）。

### 2.2 R9 — **先识别"单/双"，再剥离括号和"周"字**

```
规则：在删掉任何字符之前，先检查原文是否含 "单" → 只取奇数周；
      含 "双" → 只取偶数周；然后再剥离 (周)/周/第/括号，最后才按区间展开。
```

- **旧证据（正确实现）**：`parse_schedule_time.py:53-57`
  ```python
  text = str(week_text).replace("（", "(").replace("）", ")")
  text = text.replace("(周)", "").replace("周", "").replace("第", "")
  odd_only = "单" in text          # ← 必须在剥离之前
  even_only = "双" in text         # ←
  text = re.sub(r"[单双()]", "", text)
  ...
  if odd_only:   weeks = {w for w in weeks if w % 2 == 1}     # :72-73
  elif even_only: weeks = {w for w in weeks if w % 2 == 0}    # :74-75
  ```
  注意顺序的微妙之处：`(周)` 先删、`周` 再删，但 **`单/双` 的判断在剥离 `[单双()]` 之前**，所以 `1-16单周` 的 `单` 能被看见。

- **同一个仓库里有一份错的实现**（这是最好的教材）：`campus_api.py:129-131`
  ```python
  text = text.replace("(周)", "").replace("周", "").replace("第", "")
  text = re.sub(r"[单双()]", "", text)     # ← 直接删掉，没有先判断奇偶
  ```
  结果：`1-16单周` 被展开成 `1..16` **全部周次**。后果是"单周课在双周也被提醒"，
  而且**没有任何报错**——这就是 §4 说的静默错误。

- **为什么必须保留**：单/双是**语义**，不是格式。一旦在剥字符阶段丢掉，后续无论怎么展开都补不回来。
- **1.0 怎么写**：`core::parse::weeks::parse(&str) -> Result<WeekSet, WeekParseError>`
  1. 归一化全角括号；
  2. **先扫 `单`/`双`**（两者同时出现 → `Err(AmbiguousParity)`，不要猜）；
  3. 再剥 `(周)`、`周`、`第`、`(`、`)`、`单`、`双`；
  4. 按分隔符切 token；`a-b` → 区间（`a>b` 时交换，与 `:65-67` 一致）；
  5. 纯数字 token → 单周次；
  6. 应用奇偶过滤；
  7. **区间上界必须校验**：`week <= 30`（一学期不可能超过 30 周）；超过 → `Err(WeekOutOfRange)`；
  8. token 里有无法识别的残留字符（如 `1-16(周)第3`、`1-2周/3周`）→ `Err(UnrecognizedToken)`，**不要 `findall(\d+)` 兜底猜**。

  > 旧代码在 `else` 分支用 `re.findall(r"\d+", token)` 兜底（:70、`campus_api.py:139`）。
  > 这是"尽量解析出来"的善意，但它把**格式漂移**变成了**错误数据**。1.0 宁可失败。

### 2.3 1.0 的存储形态（与 [02-系统设计文档 §5.2](../02-系统设计文档.md) 一致）

`courses.weeks TEXT` 存**规范串**，不存展开后的 16 个数字：

| 输入原文 | 规范串（落库） | 展开（运行时） |
|---|---|---|
| `1-5,7-9(周)` | `1-5,7-9` | `{1..5,7,8,9}` |
| `1-16单周` | `1-16单` | `{1,3,…,15}` |
| `4-15(周)` | `4-15` | `{4..15}` |

- 规范串规则：`a` 或 `a-b`，逗号分隔，**全串统一后缀** `单`/`双`（要么全体有，要么全体无）；
- 展开函数必须**确定性**（同输入同输出），并在 `core::calendar` 里做单元测试（属性测试：`expand(parse(s)) == expand(parse(s))`）；
- **建议**额外保留 `weeks_raw TEXT`（原文）供"周次显示"与排障——旧 JSON 有 `周次` 原文（`parse_schedule_time.py:125`），丢了以后用户看到 `1-16单` 会以为是我们改的数字。

### 2.4 R10 — 课程记录字段映射（旧 JSON → 1.0 `courses` 表）

| 旧字段 | 旧类型 | 1.0 列 | 转换规则 |
|---|---|---|---|
| `课程名` | str | `name` | 去 `\xa0`、折叠空白（R3） |
| `星期` | `"星期一"` | `weekday INTEGER` | 表头下标 + 1（R7） |
| `开始节` / `结束节` | int | `start_period` / `end_period` | 直接（但**必须经 R10a 校验**） |
| `周次` | `"1-16单周"` | `weeks TEXT` | 规范化（R9） |
| `周次列表` | int[] | **不落库** | 由 `weeks` 展开 |
| `节次`（`"01-02节"`） | str | **不落库** | 展示用，由 start/end 重建 |
| `节`（`"第1-2节"`） | str | **不落库** | 展示用（`core::calendar::display::period_label`） |
| `开始周` / `结束周` | int | **不落库** | 由展开集合首尾推出 |
| `教室` / `教师` | str | `room` / `teacher` | 空串 → `NULL`（旧代码用 `""`，导致 `"教师": ""` 与"没有教师"不可区分） |
| **（无）** | — | `term TEXT NOT NULL` | **旧 Demo 没有学期字段**，见下 |

> **`term` 是新信息，不是重命名**：整个旧 Demo 只有一个全局 `SEMESTER_START`
> （`campus_api.py:32`），课表 JSON 里根本没有"这是哪个学期的课"。
> 迁移时**必须**把所有历史记录归入一个明确的 `term`（如 `2026-2027-1`），
> 并在首次启动时提示用户"旧课表已归入 X 学期，如不对请重新同步"——
> 否则第二个学期一同步，旧课就和新课混在一张表里。

## 3. 节次映射（产品最容易错的地方，原文保留）

### 3.1 两套编号并存的事实

学校的课表用**全天连续编号**（1-13），学生口语用**半天重新编号**（上午 1-5 / 下午 1-5 / 晚上 1-3）。

| 时段 | 全天编号 | 口语编号 | 换算 |
|---|---|---|---|
| 上午 | 1,2,3,4,5 | 上午第 1-5 节 | **相同**（N → N） |
| 下午 | 6,7,8,9,10 | 下午第 1-5 节 | **+5**（口语 N → 全天 N+5） |
| 晚上 | 11,12,13 | 晚上第 1-3 节 | **+10**（口语 N → 全天 N+10） |

### 3.2 R11 — 正反例（旧提示词原文，逐字保留）

旧 Demo 把这段写进系统提示词（`campus_api.py:37-47`），**这是它最有价值的产出之一**，1.0 不要重写、不要"优化措辞"：

| 用户说法 | ✅ 正确理解（全天节次） | ❌ 错误理解 |
|---|---|---|
| "周三下午三四节" | 第 **8-9** 节 | 第 3-4 节（当成上午）← **旧历史里真实发生过的错误** |
| "下午第 1 节" | 第 **6** 节 | 第 1 节 |
| "下午第 3-5 节" | 第 **8-10** 节 | 第 3-5 节 |
| "晚上第 1 节" | 第 **11** 节 | 第 1 节 |
| "晚上第 2-3 节" | 第 **12-13** 节 | 第 2-3 节 |
| "上午第 3-4 节" | 第 **3-4** 节 | （无需换算） |
| "第 3-4 节"（未说上下午） | 按全天编号 = **第 3-4 节** | 反问"是上午还是下午" |
| "周三下午一、二节" | 第 **6-7** 节 | 第 1-2 节 |

旧提示词里的四条硬约束（：43-46），1.0 必须全部保留：

1. **先换算再比对**，冲突判断一律用**换算后的全天节次**；
2. **不要反问**用户"是上午还是下午"（用户已经说了"下午"）；
3. 回答时写**双写法**：`下午第 3-4 节（第 8-9 节）`——用户两种编号都认；
4. 保留"考古注记"：说明"曾把周三下午三四节错算成第 3-4 节，以本规则为准"。
   这比抽象规则更管用（[../v0-审计/02-设计文档.md §7](../v0-审计/02-设计文档.md) 已总结：用模型自己的失败案例纠偏）。

### 3.3 R12 — 1.0 的实现分工（关键：不要只靠提示词）

| 层 | 做什么 | 位置 |
|---|---|---|
| 代码（权威） | `from_colloquial(period: &str, half: Half) -> Result<PeriodRange>`：`上午 +0`、`下午 +5`、`晚上 +10`；越界（下午第 6 节）→ `Err` | `core::calendar::period` |
| 代码（权威） | `overlaps(a: PeriodRange, b: PeriodRange) -> bool`：**只接受全天编号**，两段区间求交 | `core::calendar::period` |
| 提示词（兜底） | 6~8 行摘要 + 上面的正反例，**只解释"为什么"**，不承担判定 | `core::context::prompt::period_hint` |
| 工具契约 | 工具参数一律用**全天节次**（`start_period: 1..=13`），并在 schema 的 `description` 里写明"用户说'下午第N节'时先 +5" | `shared::tools::get_courses` |

**为什么不能只靠提示词**（旧 Demo 的教训，`campus_api.py:96-104` 的 `SCHEDULE_RULES` 已经膨胀到 6 条）：
软约束没有校验、不能单测、每次调用都要付 token。**同一份规则写两遍时，代码是权威，提示词必须服从。**

**反例（1.0 明确禁止）**：

| 禁止 | 原因 |
|---|---|
| 把"下午第N节"直接当全天 N 处理 | 差 5 节，冲突检测全错 |
| 用"第 1-5 节=上午"硬编码去猜时段 | 用户说"周三下午一二节"时，1-2 落在上午区间，猜错 |
| 反问用户"上午还是下午" | 用户已说明；反问是体验事故（旧提示词：:43） |
| 存"下午第3节"这类**口语值**到数据库 | `start_period` 必须是全天 1-13（`02-系统设计文档 §5.2`），口语值只在展示时生成 |

## 4. 解析必须**显式失败**（旧 Demo 最严重的教训）

### 4.1 旧 Demo 的静默点清单（每一处都真实存在）

| # | 静默点 | 证据 | 用户看到的 |
|---|---|---|---|
| 1 | 课表 JSON 读取失败 → 返回空列表 | `campus_api.py:72-81`、`:84-93`（`except Exception` 后 `return default`） | 界面一切正常 |
| 2 | 课表文件不存在 → 空列表 | 同上 | 同上 |
| 3 | 空课表被当成"数据"写进提示词 | `campus_api.py:186-189`：`"（没有读取到 schedule_time.json）"` | 模型据此回答"你今天没课" |
| 4 | 无 `<font>` 的块被丢弃 | `parse_schedule_time.py:44` | 该门课从课表消失 |
| 5 | 无课程名 / 无节次 → `return None` | `parse_schedule_time.py:114-119` | 同上 |
| 6 | 周次解析失败 → 空集合 | `parse_schedule_time.py:70` 的 `findall` 兜底；`campus_api.py:129-139` | `is_course_active` 恒 `False` → 这门课**永远显示"非本周"** |
| 7 | 列数不匹配 → `break` | `parse_schedule_time.py:183-185` | 整表错位一格（错数据） |
| 8 | `SEMESTER_START` 格式错 → **回退默认值** | `campus_api.py:107-114` | 跨学期后所有课变"非本周" |
| 9 | 脏数据 `int("x")` 崩掉整轮对话 | `campus_api.py:167` | 一句"系统开小差了"（`ai_service.py:347-348`） |

**最要命的组合是 #1+#3**：解析/读盘失败 → 空列表 → 提示词里写"没读到课表" → 模型礼貌地说"你今天没有课"。
**用户不可能知道这是故障**，他会以为这 App 的课表功能就是没用。

### 4.2 1.0 的失败契约（写进 `core::parse`）

```
规则：解析/同步的每一层都返回 Result；任何"没法解析"都是错误，不是空值；
      空课表只有一种合法来源——服务器明确返回了 0 门课（并给出"本学期无课"的提示）。
```

- 与 [03-接口文档 §8.2](../03-接口文档.md) 的既有规定一致：
  > "页面改版时解析必须**显式失败**并提示'学校页面可能已更新，请反馈'，不允许静默产出空课表（v0 的教训）"

`core::parse::ParseError` 建议枚举（UI 可据此给不同文案）：

| 错误 | 触发 | 给用户的话 | 上报 |
|---|---|---|---|
| `TableNotFound` | 找不到 `table#timetable` | "没有找到课表页面，可能还没登录或页面已改版" | ✔ |
| `HeaderInvalid` | 表头不是恰好 7 个"星期X" | 同上 | ✔ |
| `ColumnMismatch{row,expected,got}` | 行列数不一致 | "课表格式已变化，请截图反馈" | ✔ + 行列数 |
| `NoContentBlocks` | 全表一个块都没解析出来 | "课表页面结构已更新，请反馈" | ✔ |
| `PartialParse{dropped,total}` | 成功 N 个、丢弃 M 个（M>0） | "解析不完整（N/M），请核对后反馈" | ✔ + 计数 |
| `WeekParse{raw}` | 周次串无法解析 | "有课程的周次无法识别" | ✔ + **原文**（周次串不含个人隐私） |
| `TermUnknown` | 没有当前学期 | "请先选择学期" | — |

三条纪律：

1. **失败时不写库、不覆盖课表**（旧数据保持可用），只在 UI 顶部显示可关闭的错误条 + "重试 / 反馈"按钮；
2. **原始 HTML 落本地**（脱敏后仅供排查、可一键删除）：`school_sync_commit` 失败时保留 `schedule.html` 的副本，
   路径与 TTL 写进 `core::memory` 的清理策略；**不上传正文到云端**（[ADR-02](../04-ADR.md)：云端不落正文）；
3. **日志只记计数与错误码**，不记课程名/教室/教师（[02-系统设计文档 §10.2](../02-系统设计文档.md) 禁止学生信息明文出端）。

### 4.3 测试要求（否则规则会在重构中悄悄退化）

| 用例 | 断言 |
|---|---|
| 正常页面（fixture 一份真实导出的 HTML） | 得到预期条数与预期字段 |
