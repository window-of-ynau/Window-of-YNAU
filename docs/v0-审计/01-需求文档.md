## 1. 一句话定位

**把云南农业大学学生每天要跑的 6 个校园系统入口，和一个会记住你的 AI 助理，合并成一个能加到手机桌面的网页。**

它不是教务系统客户端，不是爬虫，也不存账号密码——它只做两件事：**直达**（把"查成绩"变成一次点击）和**问答**（把"我下午有课吗"变成一句话）。

## 2. 背景与产品假设

### 2.1 要解决的问题

云南农业大学学生的高频痛点，从代码里 6 条硬编码链接可反推出来（`services/campus_api.py:19-26`）：

| 场景 | 现实 | 本项目给的解法 |
|---|---|---|
| 查成绩 | 要登录 `jwgl.ynau.edu.cn`，多步跳转 | 一句话/一个按钮直达页面 |
| 看课表 | 要登录教务，且课表是 13 节全天连续编号，口语里按"下午第几节"数 | 离线解析成 JSON，再让 AI 按口语习惯回答 |
| 进教务/门户 | 三个不同域名，记不住 | 侧栏 6 个直达项 |
| 图书馆 | 内网 `10.8.225.101` | 直达 |
| 问"这周有几节课""下周三下午有课吗" | 教务系统不支持自然语言 | AI + 结构化课表 |
| 拍一张群里的课表截图 | — | 识图转文字/表格 |
| 上传培养方案 PDF 问问题 | — | 文档问答（qwen-long 长文档） |

### 2.2 隐含的核心假设（也是它所有安全问题、串号问题的根源）

> **假设：这个服务只有一个用户，就是他本人。**

这个假设贯穿整个实现，并且是**默认成立**的：

- 记忆、画像、文档状态是**进程级单例**，全局只有一份（`services/memory_service.py:20-22`）；
- 所有接口**没有任何鉴权**，`/api/clear`、`/api/profile/reset` 谁都能调（`main.py:55-107`）；
- 启动脚本**主动**用 cpolar 把 8000 端口推到公网（`start.bat`），并在启动信息里写"发给别人前先确认一下"。

即：**产品定位是"单人自用"，但交付形态是"公开发布"。这两件事直接冲突**——需求文档必须先把这条写死，否则后面每一条 NFR 都无法判定。

### 2.3 目标用户

| 用户 | 使用方式 | 现状支持度 |
|---|---|---|
| 作者本人（首要用户，单人） | Windows 本机跑 uvicorn，手机通过 CPolar 公网地址打开，加到桌面 | ✅ 完整支持 |
| 同学（次要用户，多人） | 拿到同一个公网链接 | ⛔ **不支持**：会看到别人的画像、共用一份记忆、共用一份 API 额度 |

## 3. 用户故事（按作者已实现的路径反推）

1. 作为学生，我在教室路上打开桌面图标，问"下周三下午有课吗"，它直接回答几节第几节、在哪、老师是谁。
2. 作为学生，我打"怎么查成绩"，它不废话，直接给一个可点的按钮跳到成绩页。
3. 作为学生，我把班群里的课表截图发给它，它把格子读成表格。
4. 作为学生，我把培养方案 PDF 发上去，然后问"我大二上要修多少学分"，它基于文档回答。
5. 作为学生，我随口说过"我在文艺部当部长"，之后它再回答活动安排时会考虑我的身份，但**不会每句话都叫我名字**（这条专门写进了系统提示词）。
6. 作为学生，我不想留痕，点"新对话"，之前的上下文全部清空，包括正在生成中的那条回答也不会"回魂"。
7. 作为学生，我希望它在手机上像 App：全屏、有图标、深浅色跟随系统。

## 4. 功能需求（FR）

状态词：✅ 已实现可用 ｜ 🟡 已实现但价值有限/半成品 ｜ ⚠️ 已实现但行为错误 ｜ ⛔ 未实现

### FR-01 对话问答（核心）

- **意图**：一句话问校园相关问题，拿到简洁中文回答。
- **现状** ✅：`POST /api/chat`。模型 `deepseek-chat`。system prompt 由「角色 + 画像 + 时间/周次 + 节次换算规则 + 课表数据」拼成（`services/ai_service.py:316-337`），携带最近 20 条记忆。**非流式**，前端用打字机动画伪装。
- **重构要求**：
  - 必须支持流式（SSE），否则 30~120s 白屏不可接受；
  - 必须把同步阻塞调用移出事件循环（现在一个人在等，整站连静态页都卡）；
  - 需要 `max_tokens` 与消息长度上限（实测 5 万字符消息可直接通过）。

### FR-02 意图直达（跳转）

- **意图**：识别"我要去某个系统"的意图，直接给可点按钮，不让模型编造网址。
- **现状** ⚠️：`detect_jump_target` 用**子串命中 3 个关键词**（成绩/教务/集成），命中即返回固定 URL 并**完全绕过 AI**。实测：`"教务系统密码忘了"` → 只会回一句"点击前往"，拿不到任何帮助。
- **验收**：问"成绩什么时候出""教务系统密码忘了""怎么用教务系统"时，应给出内容回答，而不是一律跳转。
- **重构要求**：改为意图分类（规则 + 模型兜底），跳转作为**建议**而非**拦截**；关键词表外置成配置。

### FR-03 课表问答

- **意图**：把教务导出的课表变成能按口语问的结构。
- **现状** ✅/⚠️：
  - 离线脚本 `parse_schedule_time.py` 把 `schedule.html` 解析成 `schedule_time.json`（支持 `------` 分隔的多课、`1-16单周`、节次区间、按块去重）——**这块做得不错**；
  - 运行时读取并注入提示词，附带"节次换算规则"（下午第 3 节 = 全天第 8 节）与"周次/单双周"判定（`services/campus_api.py:37-105`）；
  - ⚠️ 学期起点硬编码 `2026-08-31`；跨学期后所有课静默变成"非本周"；
  - ⚠️ 旧格式 JSON 的"单双周"信息在 fallback 路径会被丢弃；
  - 🟡 `GET /api/schedule` 存在但**前端从未调用**，课表没有可视化，只能靠聊天问。
- **重构要求**：学期配置化（可多学期、可归档）、提供课表网格视图 API、时区明确。

### FR-04 识图（截图/课表照片）

- **意图**：拍照/截图 → 提取信息。
- **现状** 🟡：`POST /api/vision`，走 DashScope 兼容模式 + base64 data URL。默认模型 `qwen3.7-plus`、默认 base URL 是一个**个人工作空间域名**（`ws-pqr8...`），第三方拿到代码必定 401。`/api/vision` **无大小限制**（`/api/upload_file` 有 50MB，它没有）。
- **重构要求**：模型名与端点必须可配置且有可用默认值；统一上传限额；大图先压缩再传。

### FR-05 文档问答（长文档）

- **意图**：上传 PDF/Word，基于内容回答。
- **现状** ✅（有隐患）：`POST /api/upload_file` → 百炼 `files.create(purpose=file-extract)` → 轮询至 `processed`（最长 15s `time.sleep`）→ 之后所有提问自动切换 `qwen-long` 并带 `fileid://`。**同一时刻只保留一份文档**；百炼侧的旧文件**永不删除**；接口虽然支持 `question` 参数（上传后立即回答），但前端从不传。
- **重构要求**：多文档、显式"退出文档模式"、远端文件生命周期回收、fileid 消息顺序按 qwen-long 契约校验。

### FR-06 短期记忆（对话上下文）

- **现状** 🟡：`memory.json` 存 `[{role, content}]`，提示词只取最近 20 条，但**文件永久追加、每次全量读写**；`POST /api/clear` 清空并自增 epoch（正在生成的回答不会写回）。
- **已知 Bug**：存进去的是**搜索增强后的 user_message**（含整段搜索结果），不是用户原话；并发两次对话会互相覆盖（读改写无跨请求锁）。
- **重构要求**：按会话存储、带 TTL/上限、写入走事务、存原始用户输入。

### FR-07 长期画像（"它记得我"）

- **意图**：从对话中自动抽取"学生会职务/班级职务/正在做的事/其他事实"，越用越懂你。
- **现状** 🟡：
  - 触发条件：消息包含 `PROFILE_HINTS` 中的任一字符串（**含"正在""准备""项目""目前"这种超高频词**）→ 几乎每条消息都会额外触发一次付费抽取；
  - 抽取结果：只合并 4 个字段（`merge_profile`）；列表去重后截断到 12 条；
  - **前端展示 9 个字段**（姓名/学校/专业/偏好/日程备注 + 4 个自动字段），但**后端从不写入前 5 个** → 永远空白，且没有任何接口能手动填。
- **重构要求**：可手动编辑/确认画像；抽取走异步队列 + 去重缓存（同一句不重复抽取）；明确"什么该记、什么不该记"。

### FR-08 新对话 / 清理

- **现状** ✅：`POST /api/clear` 清记忆 + 让在途回答失效；`/api/upload_file/clear` 退出文档模式；`/api/profile/reset` 只清 4 个自动字段（保留手填字段，与按钮文案"清空自动记忆"一致）。
- **缺陷**：三个破坏性接口**无鉴权、无二次确认、无 CSRF/Origin 校验**；失败时依然返回 `ok:true`（字段不存在也算成功）。

### FR-09 移动端与 PWA

- **现状** 🟡：manifest 有、`display: standalone`、`apple-touch-icon` 有、`safe-area`/`dvh`/`viewport-fit=cover` 都做了；但**没有 service worker** → Chrome 不给安装提示、离线直接报错页，PWA 名不副实。manifest 缺 192px 与 maskable 图标。
- **重构要求**：加 SW（可离线打开壳 + 缓存静态资源），补 192/512/maskable。

### FR-10 主题

- **现状** ✅：明/暗双主题，`prefers-color-scheme` 跟随，localStorage 记忆，首屏内联脚本防侧栏闪烁。
- **缺陷**：主题本身没做首屏预置 → 深色用户会闪一下白；`theme-color` 双 meta 只改了第一个；顶层 `localStorage` 未包 try/catch，隐私模式下**整个 JS 会中断**（白屏）。

### FR-11 一键启动

- **现状** ⚠️：`start.bat` 用"带参数重新调用自身"的技巧在同一个窗口跑 uvicorn + cpolar（注释解释得很清楚：cpolar 路径含空格，嵌套引号会解析失败）。
- **缺陷**：① 只检查 `.venv` 存在、不装依赖，而仓库**没有 requirements.txt**（实测缺 `openai`、`bs4` 直接 `ModuleNotFoundError`）；② 硬编码 `D:\Program Files\cpolar\cpolar.exe`；③ `--reload` 直接挂公网；④ 结尾 `taskkill /f /im uvicorn.exe` 会杀掉本机**所有** uvicorn。

### FR-12 课表离线解析工具

- **现状** ✅（独立可用）：`parse_schedule_time.py`（214 行，注释详尽，去重/单双周/多课分隔都处理了）。`parse_schedule.py`（37 行）是早期遗留：产出字段与消费端不兼容、`import` 时即读盘、无 `main()`。
- **重构要求**：把"教务 HTML → 课表"做成有测试的模块；删除遗留脚本。

## 5. 非功能需求（NFR）

> 这一节是本项目**真正的欠债区**。每条都给「现状（实测/代码事实）」和「重构后必须达到」。

### NFR-01 安全：身份与访问控制

| | |
|---|---|
| 现状 | **零鉴权**。`GET /api/profile` 直出姓名/学校/专业/职务；`POST /api/clear`、`/api/profile/reset`、`/api/upload_file` 全部匿名可调；默认还开着 `/docs`、`/openapi.json`；同时 `start.bat` 主动把端口推到公网。**任何人拿到链接 = 读你的数据 + 清你的库 + 烧你的额度。** |
| 目标 | 所有 `/api/*` 必须有身份（单用户可简化为 Bearer token/口令，多用户走 session）；破坏性操作二次确认 + Origin/CSRF 校验；生产环境关闭 `/docs`；隧道侧再加一层口令。 |
| 验收 | 不带凭据访问任意 `/api/*` 返回 401；跨站 `POST` 被拒绝。 |

### NFR-02 安全：数据隔离

| | |
|---|---|
| 现状 | 记忆/画像/文档状态是**进程级单例**，所有访客共享；第二个访客一开口就继承前一个人的画像与上下文。 |
| 目标 | 引入 `user_id`/`session_id`，数据按用户分区；单用户部署也要显式指定 default 用户，避免"分享即串号"。 |
| 验收 | 两个不同 token 的会话互不可见；A 的画像不会出现在 B 的 prompt 里。 |

### NFR-03 安全：输出与注入

| | |
|---|---|
| 现状 | 前端 `escapeHtml` **不转义引号**，Markdown 链接拼进 `href="${url}"` → 模型/文档内容可构造属性注入；全站**无 CSP**。后端把 `str(e)` 直接回显给访问方（泄露内部细节）。 |
| 目标 | CSP（default-src 'self'，禁 inline script）、URL 白名单（只允许 http/https 且转义引号）、错误对外只暴露错误码。 |
| 验收 | `<a href="...onmouseover=...">` 类载荷不再生效；响应中不含异常堆栈或密钥名。 |

### NFR-04 性能：并发与延迟

| | |
|---|---|
| 现状 | 所有 `async def` 里跑**同步阻塞**调用（LLM 30~120s、上传轮询 15s、识图 60s）→ **单事件循环被堵死**，一人提问，整站（含 `/static`）无响应。非流式，首字延迟 = 全量生成时间 + 14ms/字打字机。 |
| 目标 | 同步路由改 `def`（走线程池）或全面异步化；主链路改 SSE 流式，首字 < 1.5s；超时/重试/熔断。 |
| 验收 | 并发 5 个提问时，静态资源 P95 < 200ms；首字延迟 P95 < 2s。 |

### NFR-05 可靠性

| | |
|---|---|
| 现状 | 写文件是原子的 `.tmp + os.replace`（**这个做对了**）；但错误一律 HTTP 200 + 中文字符串，无错误码、无日志框架（全是 `print`）、无指标；JSON 损坏后静默回默认值，无备份。 |
| 目标 | 统一错误信封 + 正确状态码；结构化日志；关键路径指标（请求数/延迟/模型 token）；数据文件每日备份。 |
| 验收 | 任意失败路径都能被调用方程序化识别（`code` 字段）；日志可检索。 |

### NFR-06 可移植性 / 可复现

| | |
|---|---|
| 现状 | **无 requirements.txt / pyproject**，无 README，无 `.env.example`；`start.bat` 只认 Windows + GBK + 硬编码路径；静态目录用相对 CWD 的 `"static"`（换目录启动即崩）。 |
| 目标 | 锁版本依赖声明、`.env.example`、README（含 3 条命令启动）、跨平台启动脚本（或 Dockerfile）。 |
| 验收 | 干净机器上照 README 能起来。 |

### NFR-07 隐私与数据生命周期

| | |
|---|---|
| 现状 | 画像/记忆明文 JSON；画像在每次更新时 `print` 到控制台（会出现在公网隧道窗口里）；百炼文档永不删除；`temp/` 目录只清理从不写入（死逻辑）。 |
| 目标 | 落盘加密（或至少脱敏）、日志不打画像、提供"导出/删除我的数据"、远端文件回收策略、明确保留期限。 |

### NFR-08 成本

| | |
|---|---|
| 现状 | 每条消息可能触发 2 次模型调用（回答 + 画像抽取），命中搜索再 +1；无 `max_tokens`、无缓存、无预算上限；每次请求新建 `OpenAI` 客户端（无连接复用）。 |
| 目标 | 单次问答 token 预算 + 请求级成本上限；画像抽取去重/节流；客户端复用；上下文按需注入（课表不必每轮全量塞）。 |

### NFR-09 可访问性与兼容

| | |
|---|---|
| 现状 | **意外地好**：语义化标签、`sr-only`、`role=log`、`aria-expanded`、Esc 关闭、`prefers-reduced-motion`、`focus-visible`、`isComposing` 防 IME 误发、零 CDN、系统字体栈。欠账：弹窗无焦点陷阱、暗色对比度不足（`#3b82f6` 上白字 3.1:1）、读屏因逐字打字机反复播报。 |
| 目标 | 焦点陷阱 + 焦点归还；对比度 ≥ 4.5:1；打字机对 `prefers-reduced-motion` 关闭。 |

## 6. 范围外（明确不做）

1. **不做教务系统账号托管**：不存学号密码、不做自动登录、不做爬虫。跳转即止。（现状代码符合此约定，只有 6 条静态 URL。）
2. 不做多校区/多学校适配（文案与链接写死云南农大）。
3. 不做原生 App（只做 PWA）。
4. 不做课程表编辑/周次调整（依赖教务导出的 HTML）。
5. 不做多轮文档 RAG（只用云端长文档能力，不做本地向量库）。

## 7. 里程碑建议（给重构用）
