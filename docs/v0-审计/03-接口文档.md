## 2. 系统路由

### 2.1 `GET /`

- **行为**：`307` 重定向到 `/static/`。
- **【实测】** `GET /` → `307`，`Location: /static/`（跟随重定向后返回 `index.html`，20,050 字符）。
- **用途**：直接分享域名即可打开页面（作者注释原话）。

### 2.2 `GET /static/*`

- `StaticFiles(directory="static", html=True)`，挂在 `/static`。
- **【实测】** `GET /static/` → `200`，返回 `index.html`。
- ⚠️ `directory="static"` 是**相对当前工作目录**的：从别的目录启动 uvicorn 会在 import 阶段直接崩。

### 2.3 `GET /favicon.ico` / `GET /manifest.webmanifest`

- 均返回 `FileResponse`；manifest 指定 `media_type="application/manifest+json"`。
- **【实测】** `/manifest.webmanifest` → `200`，内容为 PWA 清单。

## 3. 对话

### 3.1 `POST /api/chat`

**请求**

```http
POST /api/chat
Content-Type: application/json

{ "message": "下周三下午有课吗" }
```

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `message` | string | 是 | **无长度上限**（实测 50,000 字符直接通过）；`Pydantic` 仅校验类型 |

**响应**（永远 200）

```json
{ "reply": "..." }
```

**行为分支（按优先级短路，看懂这个才看得懂全项目）**

| 顺序 | 条件 | 行为 | 是否写记忆 |
|---|---|---|---|
| 1 | 无文档 且 消息含 `成绩`/`教务`/`集成` | 直接返回 Markdown 链接，**不调模型** | ❌ |
| 2 | 无文档 且 消息含 `搜`/`查一下`/`最新`/`新闻`/`天气`/`大创`/`比赛` | 先调搜索，把结果拼进 user 消息 | ✅（存拼接文本） |
| 3 | 存在 `file_state.file_id` | 走 **qwen-long**（timeout 120s） | ✅ |
| 4 | 其他 | 走 **deepseek-chat**（timeout 30s） | ✅ |

**实测样例**

```jsonc
// ① 未配置密钥时的失败（注意状态码仍是 200）
POST /api/chat {"message":"你好"}
→ 200 {"reply":"系统开小差了：未配置 DEEPSEEK_API_KEY。你可以直接问我其他问题。"}

// ② 命中跳转拦截（不调模型）
POST /api/chat {"message":"怎么查成绩"}
→ 200 {"reply":"收到！请点击下方按钮直接前往：\n\n[🚀 点击前往系统](https://jwgl.ynau.edu.cn/STU/cj_default.aspx)"}

// ③ ⚠️ 误拦截：本来是个求助问题
POST /api/chat {"message":"教务系统密码忘了"}
→ 200 {"reply":"收到！请点击下方按钮直接前往：\n\n[🚀 点击前往系统](https://jwxt.ynau.edu.cn/DefaultStu)"}
```

**已知缺陷**

1. 同步阻塞：该路由是 `async def`，但内部是同步 HTTP 调用 → 一次提问阻塞整个事件循环（含静态资源）。
2. 非流式、无 `max_tokens`、无超时控制（服务端有 30/120s，客户端无限等）。
3. 所有失败都是 200 + 中文，调用方无法程序化区分。
4. 记忆存的是"搜索结果 + 问题"的拼接文本，不是用户原话。
5. 读改写无锁，并发请求互相覆盖。
6. 响应体可被模型注入 Markdown 链接 → 前端渲染时存在属性逃逸风险。

## 4. 用户画像

### 4.1 `GET /api/profile`

```json
{
  "name": "", "school": "", "major": "", "preferences": "", "schedule_notes": "",
  "student_union_role": "学生会文艺部部长",
  "class_role": "班长",
  "current_activities": ["筹备迎新晚会"],
  "other_facts": ["准备考研"]
}
```

- **【实测】** 无数据时返回 `{}`（不是带空字段的骨架）。
- ⚠️ 前 5 个字段**没有任何写入方**（自动抽取不写、也没有手动编辑接口）→ 生产上永远为空，但 UI 会展示它们。
- ⚠️ 该接口直接返回个人信息，**无鉴权**。

### 4.2 `POST /api/profile/delete`

```http
POST /api/profile/delete
{ "field": "current_activities", "value": "筹备迎新晚会" }
```

| 字段 | 说明 |
|---|---|
| `field` | 要删的字段名 |
| `value` | 仅当该字段是**数组**时生效：只删这一条；空字符串则删整个字段 |

**响应**

```json
{ "ok": true, "profile": { "...": "删除后的完整画像" } }
```

- ⚠️ 无论字段是否存在都返回 `ok: true`（不存在的字段也算"删成功"）。
- ⚠️ 若 `field` 是字符串字段却传了 `value`，行为是**删除整个字段**（语义反直觉）。

### 4.3 `POST /api/profile/reset`

- 无请求体。
- 响应：`{ "ok": true, "profile": {...} }`
- 行为：只删除 4 个**自动抽取**字段（`student_union_role` / `class_role` / `current_activities` / `other_facts`），保留 `name/school/major/preferences/schedule_notes` —— 与前端按钮文案"清空自动记忆"一致 ✅。

## 5. 文件与文档

### 5.1 `POST /api/upload_file`

**请求**：`multipart/form-data`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `file` | file | 是 | ≤ `MAX_UPLOAD_MB`（默认 50MB） |
| `question` | string | 否 | **前端从不发送**；若发送，服务端会上传后立即回答 |

**成功响应**

```json
{ "ok": true, "file_id": "file-xxx", "name": "培养方案.pdf", "message": "文件已上传，可以直接提问" }
```
（带 `question` 时会多一个 `reply` 字段。）

**失败响应**（仍是 HTTP 200）

```json
{ "ok": false, "error": "上传到百炼失败：..." }
```

**【实测】**

```jsonc
POST /api/upload_file (note.txt, 11 bytes)
→ 200 {"ok":false,"error":"上传到百炼失败：未配置 DASHSCOPE_API_KEY"}
```

**行为细节**

1. `content = await file.read()` → **先整个读进内存**，再判断大小；
2. 文件名净化：`os.path.basename` + `[^\w.\-()\u4e00-\u9fa5] → _`；
3. 上传到 DashScope 兼容接口（`purpose="file-extract"`），**同步 `time.sleep(1)` 轮询最多 15 次**；
4. 成功后**覆盖** `file_state.json`（同一时刻只支持一份文档）；
5. 远端旧文件**永不删除**；
6. 后台调用 `cleanup_temp_files()` 清理 `temp/`，但代码里**没有任何地方写入 `temp/`**（死逻辑）。

### 5.2 `GET /api/file_state`

```json
// 有文档
{ "file_id": "file-xxx", "name": "培养方案.pdf", "size": 123456, "uploaded_at": "2026-10-31 17:52:40" }
// 无文档
{}
```

- **【实测】** 无文档时返回 `{}`。
- 前端据此决定是否显示"文件已就绪"胶囊。

### 5.3 `POST /api/upload_file/clear`

- 无请求体，响应 `{ "ok": true }`。
- 行为：把 `file_state.json` 写成 `{}`，退出文档模式。
- ⚠️ **不删除**远端 DashScope 文件（只是忘掉它）。

## 7. 识图

### 7.1 `POST /api/vision`

**请求**：`multipart/form-data`，字段 `file`（image/*）

**响应**

```json
{ "reply": "图片里是……" }
```

**【实测】**

```jsonc
POST /api/vision (a.png, 48 bytes)
→ 200 {"reply":"识图失败：未配置 DASHSCOPE_API_KEY"}
```

**行为细节**

1. base64 → `data:{mime};base64,...` → 视觉模型（默认 `VISION_MODEL=qwen3.7-plus`，默认端点是一个**个人工作空间域名** `ws-pqr8...`）；
2. system prompt 用的是 `build_system_prompt()` → **会把用户画像一起发给视觉模型**；
3. `timeout=60s`；**无大小限制**（与 `/api/upload_file` 的 50MB 限制不对称）；
4. 任何异常都返回 200 + `"识图失败：{e}"`。

## 10. 外部依赖接口

| 依赖 | 端点 | 用法 | 风险 |
|---|---|---|---|
| DeepSeek 对话 | `POST {DEEPSEEK_BASE_URL}/chat/completions`（经 `openai` SDK） | `deepseek-chat`，timeout 30s，非流式 | 每次请求新建客户端，无连接复用 |
| DeepSeek 画像抽取 | 同上，`temperature=0`，timeout 20s | 仅当消息命中 `PROFILE_HINTS` | 高频词导致几乎每条都触发 → 双倍费用 |
| DeepSeek 搜索 | `POST https://api.deepseek.com/v1/tools/search`（裸 `requests`） | `{query[:128], count:5, need_content:false}`，timeout 8s | ⚠️ **该路径不在 DeepSeek 公开 API 中**，异常被吞成"（搜索超时，请直接回答用户问题）" → 功能大概率长期静默失效，建议核实后改造或删除 |
| DashScope 文件 | `files.create(purpose="file-extract")` + `files.retrieve` 轮询 | 上传文档 | 轮询用 `time.sleep` 阻塞；旧文件不回收 |
| DashScope 长文本 | `POST {DASHSCOPE_BASE_URL}/chat/completions`，模型 `qwen-long` | 消息里带 `{"role":"system","content":"fileid://..."}` | fileid 消息位置敏感（作者放在 system 队列中段），换模型易碎 |
| DashScope 视觉 | `POST {VISION_BASE_URL}/chat/completions`，模型 `VISION_MODEL` | 图片 base64 | ⚠️ 默认 URL 是**个人工作空间域名**；默认模型名 `qwen3.7-plus` 需核实 |

## 11. 目标接口设计 v1（重构草案）

### 11.1 约定变更

| 项 | v0（现状） | v1（目标） |
|---|---|---|
| 前缀 | `/api/*` | `/api/v1/*`（保留 v0 一个版本用于平滑过渡） |
| 认证 | 无 | `Authorization: Bearer <token>`（单用户也是 token，便于分享时不失控） |
| 成功响应 | 扁平 JSON | `{ "ok": true, "data": {...}, "request_id": "..." }` |
| 失败响应 | 200 + 中文 | `{ "ok": false, "error": { "code": "...", "message": "...", "request_id": "..." } }` + 正确 HTTP 状态 |
| 流式 | 无 | `text/event-stream` |
| 安全头 | 无 | CSP、`X-Content-Type-Options: nosniff`、`Referrer-Policy` |
| 文档 | `/docs` 开放 | 生产关闭 |

### 11.2 错误码表

| code | HTTP | 含义 |
|---|---|---|
| `UNAUTHORIZED` | 401 | 缺/错 token |
| `FORBIDDEN` | 403 | 越权访问他人数据 |
| `NOT_FOUND` | 404 | 资源不存在（含未知 campus action） |
| `VALIDATION_ERROR` | 422 | 参数校验失败（含超长 message） |
| `RATE_LIMITED` | 429 | 触发限流 |
| `FILE_TOO_LARGE` | 413 | 超过 `MAX_UPLOAD_MB` |
| `UPSTREAM_TIMEOUT` | 504 | 模型/搜索超时 |
| `PROVIDER_ERROR` | 502 | 上游返回错误（对外不暴露原始 message） |
| `INTERNAL` | 500 | 未捕获异常（对外只给 request_id） |

### 11.3 端点清单（v1）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/session` | 新建会话，返回 `session_id` |
| POST | `/api/v1/chat` | 一问一答（同步，保留兼容） |
| **POST** | **`/api/v1/chat/stream`** | **SSE 流式（主推荐）** |
| GET | `/api/v1/profile` | 读画像 |
| PATCH | `/api/v1/profile` | **新增**：手动写入 name/school/major/preferences（补上 v0 的死字段） |
| DELETE | `/api/v1/profile/{field}` | 删除字段（替代 v0 的 POST + body） |
| POST | `/api/v1/files` | 上传文档（支持多份，带 `expires_at`） |
| DELETE | `/api/v1/files/{id}` | 删除文档**并回收远端文件** |
| GET | `/api/v1/schedule?week=N` | 课表查询（含 `term` 参数，支持跨学期） |
| GET | `/campus/{action}` | 保留 307 白名单跳转 |
| GET | `/healthz` | 存活探针（无需鉴权） |
| GET | `/readyz` | 就绪探针（检查 DB / 密钥） |

### 11.4 SSE 流式协议

```http
POST /api/v1/chat/stream
Accept: text/event-stream
Authorization: Bearer <token>

{ "session_id": "s_xxx", "message": "下周三下午有课吗" }
```

```
event: meta
data: {"request_id":"r_123","model":"deepseek-chat"}

event: delta
data: {"text":"下周三"}

event: delta
data: {"text":"下午第 6-7 节（第 6-7 节）有课"}

event: done
data: {"tokens_in":812,"tokens_out":96,"finish":"stop"}
```

## 12. 重构时的破坏性变更清单

| 变更 | 影响 | 迁移动作 |
