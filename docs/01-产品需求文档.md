## 1. 产品定位

> **把"一个学校装一个客户端"这件事反过来：装一个客户端，把这所学校的事都办了。**

学生手机里现在有几个 App：教务、成绩、课表、图书馆、校园卡、二课……每个都要装、都要登录、都要记密码。**云农之窗的假设是：这些系统大多只是"网页 + 登录"，那么一个会记事的 App 就够了。**

它做两件事，缺一不可：

1. **直达**：左导航列全部入口，用户在 App 内 WebView 完成登录（Cookie 留在端上），之后免二次登录。
2. **问答**：右对话用自然语言办事——问课表、加日程、问规定、查资料、导出日历。

**它不是**：教务系统爬虫、不是自动打卡工具、不是聊天机器人皮肤。它的核心竞争力是**把校务数据变成可被 AI 操作的本地资产**。

## 2. 五条产品原则（冲突时的裁决依据）

| # | 原则 | 具体含义 | 违反示例 |
|---|---|---|---|
| P1 | **凭据不出端** | 学校 Cookie、用户 API Key 只存在于端侧安全存储；服务端零凭据 | 把 Cookie 上传做云端同步 |
| P2 | **隐私在本地，知识在云端** | 会话、记忆、剪枝原文、个人文件只在端上；RAG 只装公共知识 | 把聊天记录塞进云端向量库 |
| P3 | **一次导入，不做后台爬虫** | 用户点"同步"才拉数据；不做定时爬、不绕验证码 | 每天 3 点自动登录抓成绩 |
| P4 | **不执行任意代码** | 只有"能力"（读文件/写日历/查知识/调模型），没有 shell、没有任意命令 | 让 AI 跑 `rm -rf` |
| P5 | **可计费、可审计** | 每次模型调用有归属（BYOK 或套餐）与用量记录 | 一个接口能被刷爆 |

| 项 | 定义 |
|---|---|

## 4. 信息架构

```
启动
├── 左导航（校务直达，用户可排序/收藏）
│   ├── 教务系统 / 成绩 / 课表 / 图书馆 / 二课 / 校园卡 / 自习室(1.1)
│   └── 每个入口 → App 内 WebView，Cookie 复用，免二次登录
└── 主区（AI）
    ├── 会话列表（本地）
    ├── 对话（流式）
    ├── 附件（PDF/PPT 截图、Word/Excel/MD/TXT 解析）
    ├── 课表 / 日程（AI 可增删改，可导出 ICS）
    └── 设置
        ├── 模型：BYOK（协议+BaseURL+Key，可测连通）或 套餐（配额）
        ├── 知识库：本地/云端知识开关
        ├── 记忆：查看/编辑/删除/清空
        └── 隐私：数据导出、删除我的数据
```

## 5. 功能需求

> 标注：`[1.0]` 版本归属 ｜ **P0** 必须 / **P1** 应该 / **P2** 可选
> 每条给「目标 → 关键行为 → 验收」。验收必须是**可测的**，否则不算需求。

### A. 校务聚合

#### FR-A1 `[1.0]` **P0** 校务入口与 WebView 免二次登录
- **目标**：用户登录一次后，所有校务页面免登录。
- **行为**：导航项 → 内置 WebView 打开对应 URL；WebView 使用独立的持久化 Cookie 存储；App 重启后仍有效。
- **验收**：登录教务 → 杀掉 App → 重开 → 直接进教务首页（不再出现登录页），直到服务端会话过期。
- **技术边界**：Cookie 存在系统安全存储（Android Keystore / Windows DPAPI）加密后落盘，**不上传**。

#### FR-A2 `[1.0]` **P0** 手动同步（课表/成绩）
- **目标**：把校务数据变成结构化本地数据，只做一次。
- **行为**：WebView 内执行注入脚本 → 抓取页面 HTML → 端侧解析 → 结构化落库；同步按钮显示"上次同步时间"；数据超过 7 天在 UI 上标注"可能已过期"。
- **验收**：同步一次后离线可查看课表；不做任何定时/后台请求（P3）。
- **边界**：调课、补课、临时教室变更**不会自动反映**，必须用户再次同步（明确写在 UI 上）。

#### FR-A3 `[1.0]` **P1** 内网资源识别
- **目标**：图书馆等仅校内可达的地址，给出明确提示而不是白屏。
- **验收**：未连校园网时打开 `10.8.x.x` 入口，提示"需连接校园网"，并提供"连上后重试"。

### B. AI 对话

#### FR-B1 `[1.0]` **P0** 流式对话
- **目标**：首字可见，可中断。
- **验收**：P95 首字延迟 < 2s（套餐模式，暖连接）；生成中可点"停止"，已输出内容保留。

#### FR-B2 `[1.0]` **P0** 三种模型协议
- **目标**：接一家配一家，覆盖市面主流。
- **行为**：`OpenAI Completions` / `OpenAI Responses` / `Anthropic Messages` 三选一，统一成内部 `ChatRequest/Chunk/Usage` 抽象。
- **验收**：同一段对话在三协议下都能流式输出；协议差异（工具调用格式、系统消息位置）由适配层吸收，上层无感。

#### FR-B3 `[1.0]` **P1** 工具调用（Tool Calling）
- **目标**：让模型能查课表、加日程、查知识库，而不是把数据全塞进提示词。
- **验收**：问"下周三下午有课吗"触发 `get_courses` 工具，返回结构化结果；不依赖把整张课表塞进上下文。

#### FR-B4 `[1.1]` **P1** 上下文使用可视化
- **目标**：用户/开发者能看到当前上下文占比（系统/记忆/工具/RAG/用户）。
- **验收**：对话页有环形占用图，点击可看分段明细与"本次注入了哪些 RAG 片段"。

### C. 搜索

#### FR-C1 `[1.0]` **P1** 联网搜索（可插拔）
- **目标**：需要实时信息时能搜；搜不到要有明确降级。
- **行为**：优先 DeepSeek 官方搜索（**必须先验证真实可用**），备选 Tavily；搜索失败时**不再静默**，UI 明确提示"未能联网，基于已有信息回答"。
- **验收**：断网/无额度时回答不崩，且提示可辨识；不允许出现 v0 那种"异常被吞成静默失效"。

### D. 文件与知识

#### FR-D1 `[1.0]` **P0** 本地文件处理
- **目标**：常见文档不用上传就能问。
- **行为**：PDF/PPT → 渲染成图 → 视觉模型识别；Word/Excel/Markdown/TXT → 端侧文本抽取；全部**端侧解析**，原文默认不上云。
- **验收**：断网情况下能完成解析（模型调用除外）；解析失败给出可读原因（加密 PDF、扫描件、超页数）。

#### FR-D2 `[1.1]` **P1** 双层检索（公共向量 / 私有 BM25）
- **目标**：减少重复搜索、让回答有出处，同时私有资料不出端。
- **行为**（对应 [ADR-09](04-ADR.md)）：
  - **公共知识**（论文、校园规章、清洗后的公开网页）→ 云端 **pgvector + rerank**，带引用；
  - **私有文档**（培养方案、笔记、自己的 PDF）→ 端侧 **BM25**，不装模型、不上云；
  - `< 2 万字` 的文档**直接全文进上下文**，不建索引（比 RAG 更准）；
  - 定义 `trait LocalIndex`，向量实现（`bge-small-zh` int8 ≈ 24MB）留作 1.1 可插拔项。
- **边界**：**RAG 不含任何会话内容**（P2/D-04）；私有内容永不进云端索引；回答必须带 `[K:doc#chunk]` 引用，可点开原文。
- **验收**：50 条知识问答测试集，引用正确率 ≥ 80%，"编造来源"= 0；私有文档在断网下仍可检索。

#### FR-D3 `[1.1]` **P2** 容量与淘汰
- **行为**：知识库超过阈值（建议 50 万 chunk）按访问频次 LRU 淘汰；"领域 RAG"后置。

### E. Memory 与上下文

#### FR-E1 `[1.0]` **P0** 本地 Memory
- **目标**：记住用户，且只在本机。
- **行为**：会话历史、记忆条目、**被剪枝/压缩的原文**、用户图片，全部落本地 SQLite；支持查看/编辑/删除/清空/导出。
- **验收**：卸载重装即清空（无云端残留）；导出为可读 JSON。

#### FR-E2 `[1.0]` **P0** 上下文管理（压缩 + 剪枝 + 可恢复）
- **行为**：
  - 预算上限 = `min(模型上限, 256K)`；
  - 用量 ≥ **55%** 触发压缩；
  - 压缩对象优先级：工具返回 > 长文档片段 > 早期对话轮次（保留首轮意图 + 最近 N 轮）；
  - 剪枝策略：留头留尾，中间替换为 `memory://<id>` 指针；
  - 原文进本地 Memory，模型可显式 `memory.fetch(id)` 取回（满足"剪了也能恢复"）。
- **验收**：连续 50 轮对话后，上下文不超预算且能正确回答"我们最开始聊的什么"（通过 fetch 恢复）。

#### FR-E3 `[1.1]` **P1** 记忆抽取质量
- **行为**：只在明确陈述个人信息时抽取（不再用"正在/准备/项目"这类高频词触发）；抽取结果可人工确认/编辑；同一事实去重。
- **验收**：100 条消息抽样，误抽取率 < 5%；无重复条目。

### F. 课表 / 日程 / 日历

#### FR-F1 `[1.0]` **P0** 课表结构化与周次展开
- **行为**：同步 → 结构化 → 按学期起止展开为具体日期实例；跨学期归档（不硬编码某一天）。
- **验收**：任意学期切换后，课表显示正确；单双周课程不错乱。

#### FR-F2 `[1.0]` **P1** AI 管理日程
- **行为**：自然语言增删改日程（"除了今天的课，再加个 19:00 组会"）→ 冲突检测 → 用户确认 → 写入。
- **验收**：与课程冲突时提示；确认前不落库（可撤销）。

#### FR-F3 `[1.2]` **P1** ICS 导出
- **行为**：导出整学期 `.ics`，时区 `Asia/Shanghai`，含课程 RRULE 展开、可选提醒。
- **验收**：导入 iOS 日历 / Outlook / Google Calendar 均无重复、无时区偏移。

### G. 模型接入与计费（盈利模式）

#### FR-G1 `[1.0]` **P0** BYOK（自带 Key）
- **目标**：免费用户零成本使用，且我们不承担其数据风险。
- **行为**：设置里选协议 + Base URL + Key → **端侧连通性测试**（发一次最小请求）→ 加密存本地 → 请求**端侧直连**提供方，不经过我们的服务器。
- **验收**：抓包与日志审计证明 Key 未出现在任何云端请求中；Key 可一键删除。

#### FR-G2 `[1.0]` **P0** 套餐（我们的 Key，**按时间授权**）
- **行为**：套餐用户**不持有任何上游 Key**，只持我们签发的时效令牌（`exp` = 套餐到期）；请求经云端代理转发。
  **按时间计费，不做 token 记账**；token 只做 1% 抽样，用于成本监控与熔断（见 [ADR-03](04-ADR.md)）。
- **验收**：令牌过期返回 `TOKEN_EXPIRED`；单用户消耗超均值 20 倍时 1 小时内告警并限流；**反编译安装包拿不到任何上游 Key**。

#### FR-G3 `[1.0]` **P0** 配额与防滥用
- **行为**：单用户同时在途请求 ≤ 1；全局并发闸门 = 50；单轮输入 ≤ 32K token；超限 429 + `Retry-After`。
- **验收**：压测 60 并发时，第 51 个请求在 200ms 内被拒而不是拖垮服务。

#### FR-G4 `[1.1]` **P1** 支付与套餐管理
- **行为**：1.0 用激活码（后台发放）；1.1 接支付、订单、退款、发票。

#### FR-G5 `[1.0]` **P1** 用量可见
- **验收**：用户能在设置里看到"今日/本月 token 用量 + 折算金额"，BYOK 用户也能看到（用于自我控制成本）。

### H. 权限与安全

#### FR-H1 `[1.0]` **P0** 端侧能力白名单
- **行为**：只暴露能力（读文件、写日历、查知识、调模型、发起校务请求）；无 shell、无任意命令（P4）；正则/规则做**粗筛兜底**（危险 URL、敏感路径）。
- **验收**：任何路径都无法执行系统命令（代码审计 + 渗透测试各一轮）。

#### FR-H2 `[1.0]` **P0** 高风险动作需确认
- **行为**：写日程、删记忆、上传文件到云端知识库 → 弹确认；确认记录进审计。
- **验收**：未确认的动作不产生副作用。

#### FR-H3 `[1.0]` **P1** 云端 Auto Review
- **行为**：仅对**套餐模式**（我们付费）的云端请求做语义审核（模型 + 规则双审）；审核不通过则拒绝并说明原因；审核记录入库。
- **边界**：BYOK 直连不经云端，**不做审核**（也无法做）——这是 D-06 的必然结果。

#### FR-H4 `[1.0]` **P0** 数据权利
- **行为**：一键导出我的数据、一键删除账号与数据（云端 + 端侧指引）；隐私政策写清"会话内容不上云（默认）"。

### I. 多端

#### FR-I1 `[1.0]` **P0** Android + Windows
- **行为**：Flutter 一套代码；Windows 端用 Flutter Desktop 打包（.exe/MSIX）；两端共享 Rust 核心。
- **验收**：同一账号在两端的课表/日程可见（通过云端摘要同步，见 T-03）。

#### FR-I2 `[1.0]` **P1** 基础 Web
- **行为**：Flutter Web 复用，只放开"只读 + 对话"；不做完整校务导航（WebView 体验差）。
- **验收**：手机浏览器能登录、能问、能看课表。

#### FR-I3 `[1.3]` **P2** iOS / 鸿蒙
- 实验分支，不承诺时间。

### J. 运维

#### FR-J1 `[1.0]` **P0** CI
- Rust：`fmt` / `clippy -D warnings` / `test` / `sqlx migrate` 校验；Flutter：`analyze` / `test`；契约：OpenAPI 与实现一致性校验。

#### FR-J2 `[1.0]` **P0** Benchmark（重构效果的裁判）

#### FR-J3 `[1.1]` **P1** 日志管理

## 7. 商业模式（最基础版）

### 7.1 两条通道的成本结构

| 模式 | 模型费用 | 我们承担的成本 | 边际成本 | 定价 |
|---|---|---|---|---|
| BYOK | 用户自己的 Key | RAG 存储/检索、带宽、审核（不做）、服务器 | ≈ 0 | **免费** |
| 套餐 | 我们的 Key | 模型 token + 审核 + 存储 + 带宽 | 与用量成正比 | **按月 token 包** |

结论：**BYOK 是获客与口碑，套餐是营收**。因此 BYOK 不能阉割功能（否则没人用），套餐卖的必须是"省事"（不用配 Key、跨端一致、有审核兜底）。

### 7.2 定价公式（单价按实际报价替换）

```
单轮成本 = 输入token × 输入单价 + 输出token × 输出单价
实际成本 = 单轮成本 × 系数k        // k=1.15 覆盖重试+审核+压缩调用
售价     = 实际成本 / (1 - 目标毛利率)   // 目标毛利率 ≥ 50%
```

**示例**（假设输入 ¥2/百万、输出 ¥8/百万，一轮 3K 输入 + 500 输出）：

| 项 | 数值 |
|---|---|
| 单轮成本 | 0.003 + 0.004 = **¥0.007** |
| 实际成本（k=1.15） | ≈ **¥0.008** |
| 售价（毛利 50%） | ≈ **¥0.016/轮** |
| 月 300 轮套餐 | 成本 ¥2.4 → 售 **¥4.9~9.9**（毛利 51%~76%） |

## 12. 术语

| 术语 | 含义 |
|---|---|
| BYOK | Bring Your Own Key，用户自带模型 Key，端侧直连 |
| 套餐 / 云端代理 | 用我们的 Key，经我们服务器转发与计费 |
| Memory | 端侧隐私层：会话、记忆、剪枝原文、图片 |
| RAG | 云端知识层：只放非隐私知识，带引用 |
| 剪枝 / 压缩 | 上下文超预算时的降维手段，原文进 Memory 可恢复 |
| Auto Review | 只对套餐通道的云端请求做的语义审核 |
| 行为对齐 | 旧 Demo 的每个行为在新架构上等价可用 |
