# 05 · 待办事项

> 只记录**已知、尚未解决、但当前不阻塞**的问题。每条四要素：现象 / 影响 / 修法方向 / 优先级。
> 优先级：P0 上线前必须解决 · P1 影响体验但可绕行 · P2 清理与打磨。
> 责任域用方括号标注：`[客户端]` 端侧（crates/core、crates/shared 提议、app）、`[云端]`、`[文档]`。

## 客户端

### 1. `portal_api.dart` 里的空 `catch` 会吞掉脚本错误
- **现象**：注入脚本、cardId 探测、XHR hook 等处大量 `try { … } catch (e) {}`，异常既不上报也不计数。
- **影响**：页面脚本一旦因浏览器版本/改版报错，Dart 侧只能看到"没反应"（例如「cardId 无」「候选 0 个」），排查只能靠猜。
- **修法方向**：统一改成 `catch (e) { window.__yunongErrors = window.__yunongErrors || []; push({where, msg: String(e)}); }`，
  并在诊断弹窗里显示最近 5 条；Dart 侧 `SessionProbeJsBridge` 增加"取错误"入口。
- **优先级**：P1

### 2. bridge 安装失败是静默的
- **现象**：`addJavaScriptHandler(handlerName: 'yunongBridge')` 若因平台/时序没装上，页面 `postMessage` 全部丢失，Dart 侧只表现为"抓取超时"。
- **影响**：这类失败与"学校改版""没登录"混在一起，用户只会看到 `CAPTURE_TIMEOUT`，无法自证是环境问题。
- **修法方向**：`onWebViewCreated` 里装完后主动 `evaluateJavascript('!!window.flutter_inappwebview')` 回读一次，
  把结果写进诊断（`bridge=ok|missing`）；失败时直接给"请重启应用"的明确提示，而不是等超时。
- **优先级**：P1

### 3. 右键/长按文本菜单在某些页面仍是半透明（待定位页面）
- **现象**：owner 反馈"右键菜单又透明了"；但代码里 `MaterialApp.builder` + `solidSurfaceTheme` 都在，
  三主题回归测试断言 `surface / surfaceContainer / …High / …Highest` 全部 `alpha == 1.0`，**本地复现不出**。
- **影响**：菜单文字与背景混色，读不清；且因为复现不了，无法判断是哪个路由/哪一层又包了透明 theme。
- **修法方向**：真机打开「设置 → 关于 → [临时] 会话校验探针 → 环境排查（只读）」看 `surface.alpha` 与
  `builder 生效` 两行；若在某个具体页面 alpha < 1.0，就顺着该页面的 `Theme(...)`/`Scaffold` 包裹层找；
  若所有页面都是 1.0 但仍透明，则问题在 `AdaptiveTextSelectionToolbar` 的 `Material` 颜色来源，改为自定义 `ButtonStyle`。
- **优先级**：P1（需 owner 提供"哪个页面"）

### 4. 临时诊断探针必须在上线前下线
- **现象**：设置页「关于 → [临时] 会话校验探针」及相关代码仍在：`session_probe*.dart`、`card_id_hints.dart`、
  `session_cookie_diagnostics.dart`、`kCardIdProbeInstallScript` / `kGrabHtmlInstallScript` 的 UserScript 注入、
  `SessionProbeJsBridge` 静态钩子。
- **影响**：会读取页面内 `cardId`、Cookie 元信息（仅名字/域）并提供 CAS 跳转入口；正式版暴露这些能力既无必要也不合适。
- **修法方向**：验证完成后一次性删除：①设置页入口行；②`session_probe*/card_id_hints/session_cookie_diagnostics`；
  ③`webview_fetcher` 里的注入与桥赋值（`kCardIdProbe*`、`SessionProbeJsBridge.*`、`CasTicketProbe.*`）。
  **保留** `kGrabHtmlInstallScript`（PARSE_EMPTY 重试需要），但把它挪到校内抓取模块、去掉「临时」标注。
- **优先级**：P0（上线前）

### 5. 课表抓取首次 `PARSE_EMPTY`（已接线，待真机确认）
- **现象**：每次构建后第一次抓取报 `PARSE_EMPTY`，重试即好。
- **影响**：新用户第一次导入课表可能看到失败提示。
- **修法方向**：已接线 —— 页面侧 `window.__yunongGrabHtml()` 可重复调用；bridge 收到空壳 html 时 800ms 后重取一次，
  仍不合格才 `HTML_CHANGED`（诊断含 `html 长度=N / 是否含课表关键字=…（第 N 次）`）。**仍需真机验证首次是否不再报错**。
- **优先级**：P1（验证后关闭）

### 6. `ModelSelector` 的模型列表仍以「预设 + 供应商」为来源
- **现象**：t146 已按名字去重（预设优先），但若用户给自定义供应商配置了与预设同名的模型，仍会显示预设那一条。
- **影响**：极端情况下分不清"这条属于哪个供应商"。
- **修法方向**：候选改为 `(providerId, model)` 二元组，UI 显示 `供应商/模型`；去重键也变成二元组。
- **优先级**：P2
